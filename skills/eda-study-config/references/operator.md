# 操作人员使用说明

本说明用于按已核验的配置包完成准备、检查、试跑、正式运行和归档。配置助手根据研究方案与数据说明整理完整配置、记录参数依据并核验可核验的内容；操作人员提供真实材料，核对身份关系、时间信息和实际波形，并按操作卡执行、反馈结果。无法确认的事实应列为待补，不得估计代填；操作人员无需自行选择统计方法或调整分析参数。

## 交付前说明

先简要列出当前状态、可以继续的下一步、仍缺少的材料或事实，以及这些缺口会影响什么。没有实际运行能力时，明确写“配置已生成，运行校验未执行”，不要声称可以直接运行或保证正确。没有真实数据时交付草案，说明补齐材料后再生成正式包。

## 操作卡内容

| 步骤 | 操作人员要做什么 | 成功判断 | 未通过时怎么处理 |
| --- | --- | --- | --- |
| 准备 | 将原始导出、事件或条件记录、编号对应表放到指定目录；保留原始文件 | 文件名、单位、人数或会话及研究设计相符 | 保留原文件，按数据准备清单补齐信息；不要自行排序或填零 |
| 打开 | 打开已核验的软件或命令环境，并确认显示的版本 | 版本及文件哈希与配置核验记录一致 | 切换到记录中对应的目录和程序，避免混用其他版本 |
| 检查 | 运行操作卡给出的“检查配置”命令或脚本 | validate、plan 及当前版本提供的 preflight 均无阻断；导入人数和映射正确 | 保留完整错误日志交给配置助手，不要为消除错误而随意改阈值 |
| 试跑 | 使用独立的 pilot 配置，对完整的小样本运行一次 | 条件、波形和事件时间对齐；QC、有效覆盖、统计人数合理；输出没有关键缺项 | 暂停正式运行，保留日志和输出目录，交由配置助手诊断 |
| 正式执行 | 配置达到 ready_for_execution 后，运行提供的脚本 | 使用新的运行目录，状态为 succeeded；主要结局、统计结果和诊断检查通过 | 保留 partial、failed 或 cancelled 的日志和目录，不把它们视为完成 |
| 结果核对 | 按操作卡列出的实际输出文件核对人数、方向、覆盖、排除和统计状态 | 每项主要假设都有可解释的结果或明确的失败原因 | 不自行删除失败检验；由配置助手依据原方案处理 |
| 归档 | 保存原始来源、配置、操作卡、日志、版本信息和完整结果 | 完整性清单通过，配置与输入哈希可追溯 | 新版本配置另存为新包，保留旧结果 |

## PowerShell 命令约定

操作卡应填入已核验的 `$edaExe` 或 `$edaPython` 路径，以及 `$studyConfig` 配置路径。使用调用运算符 `&`，并将参数分别传入；文件名含单引号时按 PowerShell 字面量规则处理。每次外部命令运行后都检查 `$LASTEXITCODE`，非零时立即停止。还要检查 JSON 输出中的状态和阻断列表，因为某些检查命令即使退出码为 0，结果也可能不允许运行。配置发生变化后，先前的核验记录不再适用。

源码环境命令形态如下。最终操作卡必须替换为经过核对的真实路径：

```powershell
& $edaPython -X utf8 -m eda_toolkit validate --config $studyConfig --json
if ($LASTEXITCODE -ne 0) { throw '输入检查未通过，请保留日志交给配置助手。' }
```

GUI 入口、菜单及导入配置步骤应以当前已核对的界面为准，不照搬旧版本截图。若无法确认按钮名称，使用上方已核验的 CLI 操作，避免误点不存在的菜单项。

## 常见错误

| 现象或代码 | 含义 | 操作人员可提供的信息 |
| --- | --- | --- |
| `unknown_field` / `config_type` | 字段或格式与当前版本不兼容 | 软件版本、完整配置和报错 |
| 时间重复或倒序 | 时间轴可能存在重复、拼接或导出问题 | 原始导出方式及各文件记录的含义；不要自行排序 |
| 单位缺失 | 无法确定电导或电阻换算方式 | 设备导出说明、单位截图或文字 |
| `missing_planned_condition` / `insufficient_pairs` | 计划条件缺失或完整配对不足 | 哪些对象完成了哪些条件，缺失情况如何 |
| `pseudoreplication` | 同一独立单位的多行数据可能被当作独立样本 | 文件、试次、会话与对象的对应关系 |
| `clustered_independence` | 同一互动组内的依赖关系未纳入分析 | 实际组成员及随机分配规则 |
| `no_stat_observations` / `unavailable` | 结局没有合格数据 | 原始波形、有效覆盖及事件记录；不要填成零 |
| `mixed_model_nonconvergence` / `rank` | 模型无法可靠估计 | 研究设计、人数和协变量；不要通过删项来强行收敛 |
| 输出、权限或依赖问题 | 输出位置、资源或运行环境异常 | 磁盘空间、目录位置和完整错误信息；不要只提供 EXE 文件 |

## 配套脚本

以下命令供配置助手使用，操作人员无需自行填写项目路径。

`python scripts/check_bundle.py <analysis.json> --decision-log <decision-log.json> --toolkit-root <EDA 源码根目录>`：只读静态检查及源码契约检查。没有 Python 的便携环境可使用 EXE 的 validate/plan；不能因无法运行此脚本而声称已经完成核验。

`python scripts/make_demo.py --toolkit-root <EDA 源码根目录> --directory <新的空目录>`：使用已安装项目依赖的解释器，创建四个虚构对象、A/B 条件、完整配置和设计记录；不会自动运行。随后可对生成的 `analysis.json` 依次运行 validate、plan、preflight 和 run，检查从导入到配对统计的链路。生成器拒绝非空目录；所有文件仅用于工程演示。不得将演示数据中的身份、条件、采样率或默认参数复制到真实实验。示例 decision-log 用通配来源代替完整参数台账，仅供合成演示；正式研究必须逐项记录实际参数。
