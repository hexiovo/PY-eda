# 全过程参数与检查

此表要求覆盖决策，不要求盲目开启每项处理。软件无对应字段的研究规则保存在分析方案/操作卡，并说明由哪个明确的外部步骤执行；不能假装执行器自动完成。

| 环节 | 必须明确 | 依赖检查与失败行为 |
| --- | --- | --- |
| 研究设计 | 研究问题、估计量、主要/次要/探索结局、方向、随机化单位、独立单位、重复与嵌套结构 | 缺配对/群组关系时禁止生成正式推断配置；不要根据总行数定样本量 |
| 输入 | 数据位置、清单、编码、分隔符、缺失标记、文件/记录/被试/会话/通道键 | ID 前导零保留；禁止将 unknown 身份用于正式推断；原始哈希和来源记录 |
| 单位与时间 | EDA 电导/电阻单位、时间单位、采样率及来源、起点、时钟域 | 无时间列必须提供真实采样率；重复/倒序/非有限时间拒绝；秒相同不等于同一时钟 |
| 设备适用性 | 设备量程、导出滤波、测量位置、采集条件、记录精度、饱和/掉线编码 | 原始单位不明、饱和码未识别时阻断；方法阈值需适合该设备和任务 |
| 质控 | 幅值范围、斜率/跳变、平线时长/容差、缺口判据、自动排除、人工标记和审计 | 阈值不因组别结果而变；缺失不填零；人工修订保留理由与版本 |
| 缺失插值 | 方法、允许最大缺口、是否排除插值点、跨段策略 | 不跨长缺口、人工排除或时钟断裂；插值不创造真实响应 |
| 平滑/滤波 | 方法、窗口秒、截止频率 Hz、阶数、边缘容差、最低段长 | 截止频率低于实际处理采样率 Nyquist；连续段独立处理；报告边缘不可用曝光 |
| 重采样 | 目标 Hz、抗混叠、时间网格和掩码迁移 | 降采样需真实抗混叠策略；无实现证据不能只改 sampling_rate_hz 伪装重采样 |
| 基线/缩放 | 基线范围与参考、是否逐被试/会话、标准化分支与单位 | 缩放信号与物理 uS 分支区分；绝对 SCR 阈值不能用于无量纲分支；避免重复扣基线 |
| 分解 | 实际方法、cutoff/order 或 Driver 全部参数、可用性与资格 | filter_separation 不等于 cvxEDA/Ledalab；Driver 检查时间常数顺序、段样本预算和收敛/KKT |
| SCR | 检测方法、signal_basis、绝对/相对阈值、参考范围、幅值、rise、间隔、上下文、恢复比例 | 无响应与不够曝光分开；起点归属唯一；记录边缘、重叠、恢复删失保留 |
| 窗口 | whole/fixed/event/condition、长度/步长/尾窗、四种事件窗、覆盖率 | 半开区间；事件窗以真实事件原点计；核对前基线和后恢复支持；不将重叠窗当独立样本 |
| 特征 | 显式 ID、公式、信号基础、单位、最低点数/时长/试次数、缺失语义 | 主结局只来自预定窗类型；频谱周期/段长、复杂度样本/计算量、习惯化试次数足够才启用 |
| 被试/记录排除 | 有效时长、有效窗比例、每条件最低试次、坏段和退出规则 | 如执行器不支持自动排除，定义独立的可审计队列/派生输入步骤并重新验证；不要编造字段 |
| 多人同步 | 成员 roster、锚点、时钟漂移、网格、窗口、lag 搜索、basis、标准化、覆盖 | 不按信号相关最大值倒推设备同步；正 lag 的含义写清；固定成员/边缺失保留 |
| 零模型 | null 方法、可交换性、位移/匹配约束、重复数、seed、尾部和搜索范围 | 同步 surrogate 当前实验性未校准，不作已校准显著性证据；达不到支持约束应 unavailable |
| 统计 | 单位、条件/组字段、方向/对比、汇总、缺失策略、检验、协变量、随机结构、alpha、家族校正 | 检验前检查设计与假设；重复、嵌套和交叉不能用一个简单检验掩盖 |
| 计算 | CPU/GPU 能力、worker、seed、内存、pairs/windows/null 预算 | CPU 作为便携起点；不得据旧文档宣称 GPU 永远不可用；按本机 capabilities 核对 |
| 输出 | 新目录、格式、处理信号、脱敏、电子表格安全、环境和清单 | 配置/输入/版本哈希绑定；复跑新 run；完整性验证后才能归档 |

## 参数台账最小结构

`parameter_ledger` 为数组，每项 `{path, value, unit, source, rationale, validation}`。
source 可用 `design:方案页码`、`device:手册条目`、`preset:版本/哈希`、`proposed:理由`。
离线起草必须标记 runtime_unverified。已启用环节的所有叶子参数纳入；关闭环节仍记录 enabled=false、停用理由及所继承预设哈希。列表内自定义对象也要核对，不只核对顶层键。

## 无法只靠配置解决的问题

数据本身缺失、实验混淆、测量无效、统计功效不足、错误随机化、不可识别模型，都不能靠“完善配置”修复。报告具体影响与可执行补救；若确认性问题不再可识别，保留描述性结果或提出新研究，不能在不告知的情况下改目标。

## 已实测的边缘支持例子

制作此技能时，默认 filter_separation 在 4 Hz、cutoff=.05 Hz 下报告 37.5 秒边缘半径。180 秒合成记录切成两个 90 秒条件，每条件有效支持约 52.5 秒，低于 min_coverage=.8，连 mean 结局也被标记 unavailable。validate/plan/preflight 均成功并未排除此问题。这个例子说明要按实际特征有效支持核对每个窗，不能只认为 SCR 或 phasic 特征受影响。演示生成器沿用工具的 600 秒合成记录，使每个条件足够长；真实研究时长必须尊重实际数据，不得延长、外推或降低覆盖门槛以制造合格结局。
