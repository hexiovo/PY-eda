EDA ANALYSIS SOFTWARE — PHASE DELIVERY AND ACCEPTANCE PLAN
Baseline: 2026-10-25 | Revision: 1.1 | Future Codex development work only

1. HOW TO USE THIS PLAN

This document preserves P00–P14 from the supplied source. It does not execute or authorize any phase. When future development is requested, select a phase, inspect the actual repository and previous handoff, reconcile changes with these designs, and complete only the authorized work. Do not install globally, publish, push commits or continue into another phase through the authority of an embedded task example.

[RV15] Codex performs development, integration, checks and handoff. No personnel allocation, person-day estimate or team-management workflow is required. Within an authorized phase, make routine implementation choices autonomously and record consequential decisions. Ask only for unavailable facts that actually determine correctness or for actions outside the authorized scope.

All paths below are proposed FUTURE deliverables; their appearance here does not mean they exist. All acceptance cases below have status PLANNED, with no numerical/build/scientific passes recorded by this planning delivery.

Common phase contract:
  Entry: predecessors accepted or explicitly documented deviations; actual files/changes reviewed; no overwrite of user data.
  Work: implement the scoped contracts and meaningful checks; keep original files immutable; update method/config documentation.
  Exit: required build and applicable unit/integration checks pass, open failures identified, evidence indexed, scope mapped and handoff written. A skipped test is not passed evidence.
  Handoff: changed artifacts, commands/environment, tested inputs and hashes, numerical/functional results, failures, unverified claims, contract changes and next-stage dependencies.

Evidence record fields: evidence_id, requirement_id, module/phase, method/version, dataset/provenance/hash, environment, command/procedure, expected result/tolerance, observed result, status, limitations and execution/check date. Distinguish engineering, numerical, scientific, performance and packaging evidence.

3. P01 — CONTRACTS, ARCHITECTURE AND FEASIBILITY
Predecessor: P00. Modules: M01, M02, M12, M16.

Tasks:
  1. Specify recording, sample, mask, annotation, window, feature, sync and run contracts; resolve identity and clock naming.
  2. Specify all CSV dictionaries, versioned JSON schemas, error/status conventions, cache keys, progress/cancellation and exports.
  3. Create a procedural package skeleton only when this phase is authorized; unimplemented operations must raise explicit NotImplementedError rather than return artificial success.
  4. In an isolated environment, resolve a candidate runtime/dependency set and perform a minimal Qt/native-library/CLI frozen-build probe. Record failures and fallback decisions. This early feasibility task is an addition to the source sequence to reduce late distribution risk.

Future artifacts: architecture decisions, data dictionaries/schemas, interface reference, skeleton, contract tests, runtime/freeze feasibility note and candidate constraints.
Acceptance A01: core imports without Qt; schemas cover required fields/foreign keys; impossible configs fail; skeleton never fabricates outputs; feasibility evidence distinguishes a minimal probe from a qualified release.
Exit decision: runtime candidate and release-critical license blockers have an actionable path. Exact lock remains subject to subsequent qualified integration.

[RV12] Mark contracts schema-ready versus implementation-ready. Before a method is coded, resolve its formula, signal/time domain, units, threshold scope, edge/censor rules and deterministic failure behavior. Device/task-specific values may remain configurable and unqualified, but cannot be silently guessed. Add a minimal internal integration harness that will exercise real functions as P02–P08 become available; keep unimplemented skeleton stages explicitly unavailable.

4. P02 — TEMPLATES, IMPORT AND NORMALIZATION
Predecessor: P01. Modules: M02, initial M11 fixtures.

Tasks: deliver all nine template types and dictionaries; implement mappings/constants, preview, declared units, rate/time diagnostics and table linkage. Preserve identifiers and original values. Build a fixed malformed/valid input corpus and catalogue legally usable representative recordings/reference samples.
Future artifacts: templates, mapping schema/profiles, core_io functions, import reports, fixture provenance and tests.
Acceptance A02: Chinese column/path examples, leading-zero IDs, mixed/unknown units, missing EDA/time, Inf, malformed quoting, duplicate/backward timestamps, mapping conflicts and participant/anchor/event conflicts have expected diagnostics; round-trip preserves values/NA/IDs.
[RV09/RV12] Start the actual headless import→normalized-output integration case and consumed-input hashing here; extend this case in each later numerical phase. Include an input changing during import and ambiguous event-clock metadata.
Data gate: no representative real data is required to finish import engineering, but its absence must remain visible and blocks later blanket scientific claims.

5. P03 — QC AND HUMAN ANNOTATION
Predecessor: P02. Modules: M03.

Tasks: implement transparent automatic candidates, sample facts and interval segmentation; implement function-level manual annotation/history and undo semantics independent of GUI; define configurable eligibility policies.
Future artifacts: core_qc functions, annotation format/history, QC metrics/reports, candidate threshold metadata and test corpus.
Acceptance A03: flatline/jump/gap/clipping/timing cases produce traceable masks; overlapping causes survive; restore cannot invent missing observations; revisions reproduce prior decisions; data hashes are unchanged.
Only candidate logic is qualified here. Device-independent physiological cutoffs are not asserted.

6. P04 — PREPROCESSING
Predecessor: P03. Modules: M04.

Tasks: implement bounded interpolation, valid-segment smoothing/filtering, timing regularization, anti-aliased conversion, baseline/scaling and influence-mask propagation. Record operation order and boundaries.
Future artifacts: preprocessing functions and parameter schema, numeric reference fixtures, error/sensitivity plots and operation reports.
Acceptance A04: illegal cutoffs, short segments, 4 Hz and noninteger-rate data, long dropouts, pad requirements, zero variance and nonpositive log inputs behave explicitly. Quantify frequency/alias/phase/amplitude and edge error against predetermined tolerances. No interpolation/filtering bridges a long gap.
Exit decision: qualify permitted rate/length/operation combinations; defer unsupported combinations instead of silently changing the pipeline.
[RV01–RV03] Test a known affine clock map and fs_reference=fs_local/b, physical-versus-normalized threshold compatibility, forward/backward response and scientifically usable segment duration beyond the library pad-length check. Window extraction must not restart filtering at every boundary. This time-base contract is tested here; full group anchor estimation is implemented in P07.

7. P05 — DECOMPOSITION AND SCR
Predecessor: P04. Modules: M05, M06.

Tasks: implement the explicit base filter-separation route and SCR contract; preserve residual/basis/units and recovery censoring. Add cvxEDA only if its readiness/license/runtime gates are met; otherwise publish its precise unavailable status. Freeze upstream version/commit and parameters for any reference compatibility route.
Future artifacts: decomposition/SCR functions/adapters, method registry, fixed golden outputs, solver/threshold documentation and failure cases.
Acceptance A05: valid no-peak output has an empty typed table; absolute/relative thresholds are distinct; onset/peak/recovery and amplitude definitions pass hand checks; gaps/boundaries/overlap/censoring are tested; unit-transform recovery and residual diagnostics agree with the selected implementation.
Scientific gate: a reference match demonstrates faithful implementation, not latent physiological truth or cross-device validity.
[RV05] Verify reference_scope for relative thresholds, resolved threshold invariance under a change of analysis windows, recovered-versus-remaining fraction semantics and SCR area bounds. Deliberately changed segmentation may alter method results, but must not silently alter the configured relative reference scope.

8. P06 — SINGLE-PERSON WINDOWS AND FEATURES
Predecessor: P05. Modules: M06 attribution, M07.

Tasks: implement whole-record/fixed/event/condition windows; event-SCR link table; registered features; duration/coverage calculation and metric-specific validity. Record zero-inclusive and detected-response-only amplitude definitions separately.
Future artifacts: window and feature functions, feature dictionary, validity tables, hand-calculable fixtures and end-to-end single-record evidence.
Acceptance A06: valid zero response, no usable time, contaminated baseline, overlapping stimuli, unrecovered responses, partial tail and irregular-time exposure produce correct values/statuses/units. Rate uses eligible minutes. Cross-bad-segment event windows remain invalid under primary policy.
Milestone G2: a trustworthy internal single-record workflow exists; GUI/CLI/group/release obligations remain outstanding.
[RV04] Verify point-sample exposure on a minimal regular/irregular grid, no extrapolated final interval, exact window-boundary onset assignment, and detector-context exclusions in the rate denominator. Preserve sample count separately from eligible duration.

9. P07 — CLOCK ALIGNMENT, GROUP SYNCHRONY AND NULLS
Predecessors: P04 and stable P05 component outputs; P06 supplies compatible windows/validity. Modules: M08, M09.

Tasks: implement group linkage, clock offset/drift with uncertainty, shared-grid eligibility, signed lag-zero/window/lag metrics, group/leave-one-out summaries, temporal surrogate and matched pseudodyad capability. Validate coherent participant-level randomization, coverage comparability, selection-aware statistics and explicit inference limits.
Future artifacts: alignment/metric/null functions, group schemas, pair/lag/coverage/null tables, simulated validation suite and design notes.
Acceptance A07: offset/drift and lag signs correct; two-anchor precision is not overstated; unverified timing/zero variance/insufficient shifts are unavailable outcomes. Repeat null simulations with confidence intervals, known ±coupling/delay, common trend/stimulus controls, missingness and membership changes. Observed/null computations repeat the same lag/window search. Pseudodyads require matching metadata and exchangeability.
Claims gate: only a temporal null supports only its temporal question; unavailable partner-specific inference is not replaced with a stronger verbal conclusion.
[RV06–RV08] Distinguish approximate surrogate tails from justified randomization p-values. Test pair-relative shifts, an infeasible joint-shift configuration, capped attempts, coverage/member-set matching, fixed sampling precision and no significance-based stopping. Verify equal-pair versus across-group weighting and stable leave-one-out membership. Uncalibrated inferential regimes remain experimental even if arithmetic tests pass.

10. P08 — STATISTICS AND FIGURES
Predecessors: P06; group inference additionally requires P07. Modules: M10, plot portion M11.

Tasks: implement design validation, descriptive/one-sample/paired/independent comparisons, independent-unit correlation and qualified linear mixed models; effect sizes/intervals, exclusions, correction families and diagnostics. Build figures using result contracts.
Future artifacts: design schema/templates, statistical functions, plotting functions, reference outputs and inference validation.
Acceptance A08: subject/group/session counts distinct from window counts; invalid hierarchy and unsupported dyad structure blocked; missing covariates/excluded pairs reported; nonconvergence/rank deficiency explicit; correction families reproduce reference outputs; units/coverage/error-band definitions visible in figures.
Milestone G3: analytical/group workflow is usable through internal functions with declared scientific limits.
[RV10/RV11] Test rejection of executable formula text, strict structured design terms, planned versus tested family counts, missing tests and an incomplete planned group. Runtime failures cannot silently become statistical exclusions that redefine the requested analysis.

11. P09 — PUBLIC CLI, JSON AND COMPLETE RUN ORCHESTRATION
Predecessors: P02–P08 compatible outputs and P01 control contracts. Modules: M01, M11 export, M12.

Tasks: complete version/capabilities/validate/plan/run/resume/retry/export commands, presets, schema migration policy, deterministic seeds, provenance/cache and atomic exports. Produce reports from real computed contracts.
Future artifacts: CLI entry, shared run_pipeline, resolved-plan preview, presets, output manifests/reports and CLI integration evidence.
Acceptance A09: repeat-run numerical agreement at declared tolerance; config/event/QC changes invalidate affected cache; record failure yields partial status; interruption during computation/export leaves recoverable completed artifacts; resume validates checksums; exit codes and machine stdout are stable.
No GUI-specific calculations enter the CLI implementation.
[RV09–RV11] Test immutable run snapshots, changed source/config/annotation content, duplicate JSON keys, NaN/Infinity literals, concurrent writes, stale/incomplete manifests and downstream dependencies after partial record failure. P09 completes the public lifecycle; it is not the first numerical integration.

12. P10 — GUI

Milestone G4: usable GUI and CLI share one numerical implementation.
[RV09] Test edits during a running task and a delayed preview response after selecting another record. The active run snapshot/results must remain associated with their original run and inputs.

13. P11 — MEASURED PERFORMANCE AND RESOURCE CONTROL
Predecessors: correctness baselines P09/P10; early measurements can be collected earlier. Modules: M14.

Tasks: define benchmark suite and supported workload envelope; profile end-to-end execution; implement memory-bounded CPU parallelism; qualify frozen-process behavior; only investigate GPU for demonstrated bottlenecks. Preserve seeds and coherent group nulls.
Future artifacts: profiling/benchmark report, resource configuration and validated parallel/backend implementation where justified.
Acceptance A11: same scientific outputs/tolerances, stable seeds across scheduling, bounded workers/queues/memory, safe cancellation and no orphaned process. GPU evidence includes cold/warm initialization, transfers, synchronization, peak memory and complete-pipeline time.
Exit decision: unsupported/unhelpful GPU remains disabled; completing P11 does not require inventing a GPU implementation.
[RV14] Test resource rejection before allocation and bounded batching for large pair×window×lag×replicate workloads. Never silently chunk a whole-record solver, reduce the sampling rate or lower surrogate repetitions to make a test finish.

18. RELEASE-LEVEL VALIDATION CATALOGUE

V01 Input contracts: encodings, IDs, units, missingness, malformed files and relationships.
V02 Time/data integrity: physical timestamps, clock drift, gaps, events and sample-grid round-trips.
V03 QC audit: transparent candidates, overlapping flags, revisions, restoration and source immutability.
V04 Numerical processing: filtering/alias/edge error, scaling and influence-mask propagation.
V05 Decomposition/SCR: fixed upstream comparison, residuals, response matching, overlap and censoring.
V06 Feature semantics: hand arithmetic, integrals, exposure, valid-zero/NA and event ambiguity.
V07 Synchrony inference: repeated null simulations, lag signs, ±coupling, shared stimulus and membership.
V08 Statistics: analytical units, missing cases, reference estimates, diagnostics and multiplicity scope.
V09 Application lifecycle: config binding, GUI/CLI consistency, capability failures, cancellation/resume.
V10 Reproducibility: stable seeds, config/input/annotation/cache versions and environment differences.
V11 Resources: workload-specific time/memory, serial/parallel agreement and conditional GPU.
V12 Distribution/docs: clean Windows, frozen processes, offline help, actual screenshots and notices.
V13 Scientific utility: representative device/task data, independent annotations, pilot/held-out separation, sensitivity and raw/no-correction arms.

For each method/rate/length regime, select justified atol and rtol where relevant and report |candidate−reference| plus domain-relevant amplitude, latency, integral or statistical differences. Exact discrete identities/statuses should match exactly. Floating-point equivalence does not require byte-identical reports. Null rejection-rate qualification uses repeated simulations and a prespecified precision plan, not an invented single-example tolerance.
