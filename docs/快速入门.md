# 快速入门

适用版本：EDA Toolkit 0.2.0。本文给出当前 CLI、图形界面与合成演示的实际入口。真实研究数据使用前，先阅读 [方法指南](方法指南.md) 与 [验证与限制](验证与限制.md)。

## 1. 使用项目解释器

在项目目录 D:\program\EDA 打开 PowerShell：

~~~powershell
& '.\.venv\Scripts\python.exe' -m pip install -e '.[dev]'
~~~

运行时、依赖和实际版本记录在 [来源记录](provenance.md)。命令显式指定 .venv；不要使用可能指向 Python 3.15 的 py 启动器来复现本文命令。

## 2. 查看命令

~~~powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m eda_toolkit --help
& '.\.venv\Scripts\python.exe' -X utf8 -m eda_toolkit version
& '.\.venv\Scripts\python.exe' -X utf8 -m eda_toolkit capabilities --json
~~~

核心子命令包括 validate、plan、run、resume、retry、export、presets、templates 与 demo。validate 读入配置及关联表并报告完整导入校验；plan 预览阶段、输入和能力门槛；run 调用与 GUI 相同的 pipeline。

## 3. 先用演示数据

仓库里的 examples/synthetic_demo 是固定种子的工程演示数据，包含四条 4 Hz、600 秒记录及配套事件、条件、成员和同步锚点。所有数据均标记 SYNTHETIC_ONLY。它用于检查导入、计算、图表和导出路径，不作科学效应示例。

~~~powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m eda_toolkit validate --config examples/synthetic_demo/single.json --json
& '.\.venv\Scripts\python.exe' -X utf8 -m eda_toolkit plan --config examples/synthetic_demo/single.json --json
& '.\.venv\Scripts\python.exe' -X utf8 -m eda_toolkit run --config examples/synthetic_demo/single.json --json
~~~

运行结果会写入该配置指定的新输出目录。成功状态只表示这条工程路径完成；summary 中 science_qualification 仍是 pending_representative_real_data。

也可以在一个新的空目录中生成另一份确定性演示：

~~~powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m eda_toolkit demo --directory 'D:\eda-demo-new'
~~~

目标目录不得已含有数据。示例的行数、阈值或事件数不应作为仪器规范。

## 4. 用自己的数据

1. 复制一份 JSON 预设，在 input 中声明信号或 manifest 路径，在 mapping 中声明列名、单位、采样率与时钟域。
2. 按 [CSV 字段字典](CSV字段字典.md) 准备信号、参与者、事件、条件和其它关联表。只加入所需表。
3. 先运行 validate。若时间重复、倒退、缺失，程序会拒绝，不会自动排序或删除样本。单位未知时必须手动声明。
4. 查看导入诊断与 plan 输出，确认有效时长、映射和能力门槛。
5. 再运行 run；保存完整 JSON 输出、来源目录及 manifest。

时间列缺省时，必须提供采样率和 time_unit；生成的时间会被标为推导值，不能恢复原设备漏采信息。幅值 NaN 作为缺失保留，绝不转成 0。自定义幅值列必须显式指定 eda_unit；标准列名 eda_uS 例外，按 uS 解释。

## 5. 启动 GUI

~~~powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m eda_toolkit.ui.app
~~~

若已安装命令入口，也可在已启用 .venv 的终端运行 eda-gui。首页的“在输出目录创建并载入合成演示”会创建新的 SYNTHETIC_ONLY 示例目录；“单文件试跑”“批量启动”“取消运行”调用同一 pipeline。真实数据操作顺序和每页截图见 [操作指南](操作指南.md)。

## 6. 结果与下一步

运行目录含 resolved_config.json、provenance.json、summary.json、manifest.json、报告 HTML、结果表和图像。按运行命令请求的格式，结果表可写 CSV、JSON、XLSX；图为 PNG。manifest 记录导出产物的大小与 SHA256，resume 会校验已提交缓存和输入是否变更。

schema 1.1 的扩展指标与附属表说明见 [扩展指标与结果表](扩展指标与结果表-v1.1.md) 和 [完整指标字典](特征字典-v1.1.csv)。原 [特征字典](特征字典.csv) 保留 v0.1 原 33 项定义。结果页的“查看本次运行定义…”读取当前所选 run 冻结的 `feature_definitions.json`、配置和 manifest 表头；查看任务历史结果时也以该历史 run 保存的定义为准，不用当前编辑器草稿重解释动态指标。

报告展示不可用、删失、歧义等状态与原因。不要将缺失的估计值解释为零，也不要仅凭一条运行成功消息判断研究假设。阅读 [方法指南](方法指南.md) 了解定义，阅读 [验证与限制](验证与限制.md) 了解未完成的证据关口。
