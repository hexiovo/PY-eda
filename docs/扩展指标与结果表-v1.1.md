# 扩展指标与结果表（schema 1.1）

本文补充说明工作台 1.1 配置可用的扩展指标与运行产物。旧版 [特征字典.csv](特征字典.csv) 保持原样，记录原 33 项指标定义；完整目录见 [特征字典-v1.1.csv](特征字典-v1.1.csv)。

## 指标目录与选择

完整能力目录包含 144 项（含 9 项 Driver，详见 [Driver 方法](driver-method.md)）：原有 33 项、扩展时域/事件/SCR/群体指标，以及默认频带和滞后对应的频谱、自相关与复杂度指标。目录不是任一预设都会计算的项目清单：single 预设当前适用 124 项，启用多人同步的 group_sync 预设适用 135 项，关闭扩展计算时适用原有 33 项。禁用的指标仍显示在选择表中，并说明需要启用的功能。

`features.ids=[]` 表示使用该配置当时的全部适用指标，不表示不计算任何指标。显式选择列表则只请求所列指标。UI 在已选指标将因关闭扩展家族或多人同步而失效时会阻止该设置变更；动态频带和滞后 ID 随配置生成。

频带 ID 由 `bands[].id` 产生，例如 `clean_bandpower_eda_045_025_uS2`；滞后 ID 使用规范化秒数，例如 `clean_autocorr_lag_1s`。用户更改频带或滞后后，具体 ID 和参数以该次运行保存的 `feature_definitions.json` 为准。结果页“查看本次运行定义…”从所选运行的冻结文件读取定义，不会用当前草稿解释历史运行。旧运行未保存冻结定义时，界面会明确显示无法核对，不会推测补齐。

## 新增的 34 项常用指标（2026-10-27）

- clean 和 tonic 各新增 9 项：最小值、最大值、P05/P25/P75/P95、偏度、超额峰度和 MAD。分位数按线性插值；偏度使用调整后的 Fisher-Pearson 系数（至少 3 个样本），超额峰度使用无偏 Fisher 定义（至少 4 个样本，正态分布参照为 0）。MAD 是 `median(abs(x-median(x)))`，不乘 1.4826。常量或数值上近似常量信号的偏度、峰度不可用。
- SCR 幅值新增 4 项：逐响应平方根、`ln(1+A/1µS)`、当前记录 Z 值、当前记录最大值校正的均值。先对每条幅值变换，再求窗口均值；平方根单位为 `sqrt_uS`，对数与最大值校正无量纲。
- 事件试次序列新增上述 4 项的零包含版本：有效无响应试次的幅值为 0；排除试次保持缺失，不参加参考统计。平方根和对数后的无响应仍为 0；Z 变换后的零响应一般不等于 0。
- SCR 上升时间、配置恢复时间、50% 恢复时间、63% 恢复时间各新增中位数和样本标准差，共 8 项。标准差使用 `ddof=1`，至少需要 2 个已观察到的有效时长。恢复汇总只使用已完成的恢复；混有删失时标明排除理由，全为删失时保持 `censored`。

**标准化范围：**同一 recording/subject/session/channel 当前完整记录，跨条件取参考，不按每个窗口或条件重新归一化，也不合并其他记录、被试、会话或通道。SCR 参考为合格且 onset-eligible 的响应；事件参考为该记录全部有效试次（含真实无响应零值）。Z 值为 `(A-reference_mean)/reference_SD`，参考 SD 使用 `ddof=1`；最大值校正为 `A/reference_max`，不减最小值。参考不足 2 条或 SD 为零时 Z 值不可用；参考最大值为零时最大值校正不可用。整条记录的 Z 均值接近 0 是定义所致，主要用于比较子窗口或条件。该范围是记录内描述性校正，不是跨会话校准或训练集标准化。

`scr_events_extended` 保留原 `amplitude_uS`，增加 `amplitude_sqrt/log1p/recording_z/recording_max_fraction`；`trial_table` 保留 `amplitude_zero_uS`，增加相应 `amplitude_zero_*` 列。每个变换均有 `_status`、`_reason`，并记录 `amplitude_reference_scope/n/mean_uS/sd_uS/max_uS` 供核对。原始 `scr` 表不变。

这些指标由统一注册表接入“分解与 SCR”页的指标选择器及 CSV/JSON/XLSX 等输出。旧版便携包的 101 项目录属于旧构建快照。

## 通用结果约定

`features` 是长表，标准列为：

`recording_id, subject_id, session_id, window_id, feature_id, value, unit, basis, method, status, reason, valid_n, valid_duration_s`

`value` 不能脱离 `status`、`reason`、`unit`、`basis` 和有效时长解释。无法计算、支持不足、歧义或删失的值保留状态与原因；不可用值不应改写为零。零只表示公式定义允许且有效支持足够时观察到的零。

样本分位数使用线性 percentile method。原有 `iqr=Q75-Q25` 在一个合格样本时定义为 0，因此最低样本数为 1；其余指标按各自字典中的 `min_n` 判断支持。

运行目录中的 `manifest.json` 列出实际生成的表文件及校验值。结果页帮助窗读取本次 manifest 中表的实际文件名和 CSV 表头，因此输出格式不同或某张表为空时，应以当前运行文件为准。合并多记录的附属表会带上对应的 recording/subject/session/channel 身份列。

| 表键 | 内容与主要字段 |
| --- | --- |
| `trial_table` | 每个计划事件试次一行。列为 `trial_id, recording_id, channel, subject_id, session_id, event_id, trial_ordinal, condition, event_type, event_onset_s, baseline_start_s, baseline_end_s, response_start_s, response_end_s, trial_status, reason, response_present, amplitude_zero_uS, amplitude_conditional_uS, peak_latency_s, baseline_mean_uS, baseline_sd_uS, response_mean_uS, response_change_uS, linked_scr_ids, series_id`。无效或歧义试次保留排除理由，不作为无响应零值。 |

| `trial_fit_diagnostics` | 列为 `series_id, feature_id, status, reason, valid_n, parameters_json, rmse, jacobian_rank, converged, initialization_json, method`，跨记录合并时加 `recording_id, subject_id, session_id, channel`。 |

| `complexity_diagnostics` | 自相关与复杂度审计表。基本列为 `recording_id, window_id, family, feature_id, status, reason, parameters_json, diagnostics_json`；合并表另含 `subject_id, session_id, channel`。诊断字段可记录实际滞后网格、排列熵 ties、样本熵预算和 DFA scales/拟合信息。 |

| `scr_events_extended` | SCR 候选目录，包含原有 43 列及幅值变换、参考统计字段：原 SCR 基础列与扩展 onset/peak level、阈值/basis、onset 资格、`segment_id`、上升斜率、50%/63% 恢复交叉与状态、50% 半高宽状态等字段，并有 `subject_id, session_id, channel`。完整列名由实际运行结果页按 run manifest 展示。它保留候选级审计信息；窗口汇总仍在 `features`。 |

扩展表即使没有可用记录也可能以空表输出。空表表示本次运行没有该表的行，不表示零效应或“没有响应”。

## 群体时序表

群体时序分析使用已通过 clock mapping 的 reference 秒、预定成员与固定边集合。相关值缺失不会被当作零，负相关表示反向同步，不等同于不存在同步。

| 表键 | 列 |
| --- | --- |
| `group_temporal_features` | 与 `features` 同结构：`recording_id, subject_id, session_id, window_id, feature_id, value, unit, basis, method, status, reason, valid_n, valid_duration_s`。此表把 `group_id` 存在 `recording_id` 字段；群体项不是个体记录。 |
| `sync_episodes` | `group_id, session_id, metric, basis, sign, start_s, end_s, observed_duration_s, left_censored, right_censored, member_set, edge_set, window_ids, status, reason`。边界或支持中断时片段可为删失；平均持续时间只使用完整片段。 |
| `node_strength` | `group_id, session_id, subject_id, window_id, metric, basis, signed, positive, negative, absolute, normalized_signed, effective_degree, expected_degree, coverage, status, reason`。`expected_degree` 来自冻结成员 roster 的完整图；`effective_degree` 记录当前观测到的边数。缺失边使其两个端点的节点强度（含标准化值）不可用，理由为 `NA_missing_fixed_incident_edge`，不以较小的观测 degree 代替预定 degree。若没有成员 roster/预定图，理由为 `NA_expected_graph_unknown`。例如三人完全图预期 degree 恒为 2；若 BC 缺失，B/C 不可用，A 在 AB、AC 均可用时仍可有效。群体固定边汇总继续按缺失固定边规则报告不可用。 |
| `group_temporal_diagnostics` | `group_id, session_id, metric, basis, status, reason, analysis_duration_s, valid_class_duration_s, unknown_duration_s, positive_duration_s, negative_duration_s, neutral_duration_s, window_count, support_segment_count, member_set, edge_set`。 |

`sync_lag_sd_s` 和 `sync_lag_stability_proportion` 使用由窗口中心定义的非重叠 midpoint time cells，而不使用可能重叠的原始窗口宽度作为权重。每个 cell 与该 pair 实际连续合格支持相交后的时长是权重；支持缺口保留为未知。先逐 pair 计算，再对有效 pair 等权平均，不能把 pair 的观测合并成一个池。滞后稳定比例以时长加权中位数为中心，并计算落在配置容差内的有效时长比例；`sync_lag_sd_s` 使用总体加权标准差（`ddof=0`）。例如窗口中心 2、4、8 秒对应权重 3、3、4 秒，选中滞后 0、0、2 秒时，加权均值为 0.8 秒、加权标准差为 `sqrt(0.96)=0.9797958971` 秒；容差 1 秒时稳定比例为 0.6。

群体指标属于固定图或群体时段的描述，不增加独立参与者数量，也不能作为独立被试推断。循环移位尾部概率和复杂度指标当前为研究/工程实现，不等同于已校准的科学显著性或真实任务资格。

## 指标解释边界

- `*_unrecovered_*_proportion` 表示在可审查支持内未观察到恢复的比例，包含右删失；不能解读为生理上未恢复的比例。
- 事件 trial 的 `amplitude_zero_uS` 对有效试次中的真实无响应编码为 0；排除、污染或归属不清的试次不填成 0。`amplitude_conditional_uS` 只对有响应试次定义。
- 频谱、样本熵、排列熵和 DFA 使用 clean 信号及单个连续均匀窗口，不跨缺口拼接。样本数、频率分辨率或比较预算不满足时返回具名不可用状态，不自动缩短参数来生成值。
- 新增方法及默认参数仍是研究示例。合成数据和工程测试不能证明真实设备、任务、人群的科学适用性；请结合本次 run 的资格字段及 [验证与限制](验证与限制.md)。
