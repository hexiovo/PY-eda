# 函数开发指南

本项目核心层使用中文说明的过程式 Python 函数、普通 dict、NumPy ndarray 和 pandas DataFrame。核心算法不依赖 Qt；GUI 仅通过 core_io 与 pipeline 的 API 调用实现，不从控件内部复制文件解析或科学公式。不要为单次分析新增隐式全局状态或让数值函数写文件。

## 核心数据形状

### Record

contracts.make_record(time_s, eda_uS, metadata, *, sample_index=None, extras=None) 校验并复制等长数组。标准 record 字段为：

- metadata：recording_id、subject_id、session_id、channel、来源路径/哈希/单位、fs_hz、fs_declared、fs_estimated、时间原点、时钟域及 mapping_revision 等来源信息。
- time_s：有限、严格递增的秒。
- eda_uS：物理微西门子幅值；原始缺失保持 NaN，不能改成 0。
- sample_index：来源样本索引。
- extras：未解释的原始列、源时间字符串及扩展字段。

core_io 还给文件表写入 attrs.source_path、attrs.source_sha256；import_report.consumed_inputs 按路径记录实际消费字节的哈希。不要重读文件来覆盖已经消费的 hash。

### QC / Processed / Bundle

QC 字典保存原始 quality facts、eligible / processing_eligible / detector_eligible、半开 index segments、时间 intervals、summary 和 annotation_revision。facts 保持重叠原因，不要压成一列 good/bad。

Processed 保留 raw record 快照并增加 clean_uS、analysis_signal、analysis_unit、quality、operations、采样网格和处理报告。缩放只作用于 analysis_signal；clean_uS 保持物理值。

Bundle 增加 tonic_uS、phasic_uS、residual_uS、driver、方法/单位/基础、分解报告和 SCR detector 支持。当前 filter separation 的 driver 是 None。

## 推荐调用顺序

~~~python
records, tables, import_report = load_recordings(
    config["input"].get("manifest"),
    config["mapping"],
    config,
)
if not records:
    raise ValueError("没有可处理的记录")

record = records[0]
qc = build_quality_mask(record, config, config["qc"].get("annotations"))
processed = preprocess_record(record, qc, config)
bundle = separate_tonic_phasic(processed, config)
scr_table, scr_report = detect_scr(bundle, config)
windows = build_windows(record, tables.get("events"), tables.get("conditions"), config)
features, validity = extract_window_features(bundle, scr_table, windows, config)
~~~

上例只演示类型和顺序；批处理、群体时钟、统计、缓存和输出应通过 pipeline/controller 执行。读取 None 表、空表或无效窗口时，保留 schema 列和 explicit status，不构造伪数值。

## 实现约定

1. 函数 docstring 使用中文，说明物理单位、时间支持、参数、缺失处理、边界和错误条件；算法实现写清来源与版本，不把独立实现冒称库兼容。
2. 时间单位统一秒，物理导电率统一 uS。显式源单位才能转换；变换信号必须另有 basis/unit，不能按列名猜。
3. 对输入数组采取 copy-on-write 或构造新结果；未声明的源字段放在 extras 并留 provenance。
4. 缺失值继续 NaN，Inf 以稳定输入错误拒绝。可用状态 unavailable/censored/ambiguous/invalid 及 reason 表达失败，不填 0 伪装成功。
5. 区间使用半开 [start,end)，不跨 QC/长 gap，不为尾点外推曝光。每个变换报告实际使用段、阈值、采样率和边缘支持。
6. 从 config.resolve_config 获取严格、规范化配置。拒绝未知键、公式字符串、重复 JSON key 和 NaN/Infinity 字面量。
7. 文件读写只放在 core_io/core_export；数值模块不得写磁盘。耗时批处理接受 progress_callback 和 cancel_callback。
8. 添加回归时选定确定性 fixture、单位和 oracle。源记录、输入 hash、manifest 与 QC 历史都要检查是否保持合同。

## 错误与测试定位

输入/配置错误统一经 errors.fail(...) 报稳定 code、stage、record_id、field、message 和 remedy。CLI 将这些结构化字段写入 JSON；GUI 展示同一诊断和运行日志。

本仓库已有 tests/test_contracts_config.py、tests/test_io_qc.py 与 tests/test_independent_validation.py。新增函数应加最小边界回归，不要把“模块能 import”当数值验证。当前实际执行证据与未覆盖项列在 [验证与限制](验证与限制.md)。
