EDA皮电分析软件完整方案
版本 1.0 完整研究与分阶段执行方案
日期 2026年10月25日

交付边界
本文件是供后续分阶段执行的开发方案，不是已完成的软件。当前不安装、不开发、不运行分析。用户每次选择一个阶段执行，阶段完成后报告结果并停止，不自动进入下一阶段。已完成本文件所列原始文献、官方源码、包发布元数据与许可的静态核验；没有执行依赖解析、安装、数值测试或Windows构建。文献支持不等于当前软件已实现或已验证。

一 目标与确定需求
构建 Windows 皮肤电活动 EDA 分析工具，覆盖 CSV 导入、质量控制、预处理、tonic/phasic 分解、SCR 检测、事件及连续数据特征、单人与多人同步分析、统计、绘图和导出。界面版与无界面批处理版共用同一核心函数，不出现两套计算逻辑。
优先 Python 技术路线，语言本身不限制。终端用户优先下载后双击 EXE 使用，不依赖 MATLAB；源码运行可以依赖兼容版本 Python。Python 3.14 优先作为发布验证候选，3.12仅作为兼容备选；二者都须完成依赖解析、数值和打包实测，不先承诺最终组合。优先 one-folder 便携包，稳定后再提供安装包或单文件 EXE。
核心坚持面向过程：每个函数一件事，输入输出明确，不写业务类继承体系；UI 仅调用函数。第三方 GUI 库自身使用对象并不等于核心采用面向对象。若用户要求连 GUI 层也完全无类定义，采用模块函数与框架现成组件，不自行设计业务对象。
所有算法函数写中文注释，说明算法公式/步骤、单位、参数、假设、失败条件、缺失值处理、文献和第三方实现来源。交付使用指南、方法指南、函数开发指南及真实软件截图版操作指南，软件内可打开 PDF。软件未开发前不伪造真实截图。

二 总体结构
入口：界面入口 eda_gui.exe；无界面入口 eda_cli.exe；二者调用 run_pipeline(config, input_manifest)。
建议目录：core_io、core_qc、core_preprocess、core_decompose、core_features、core_sync、core_statistics、core_plot、core_export、ui、cli、templates、presets、docs、tests、third_party。
核心函数不弹窗、不读取 GUI 状态、不隐式修改原文件。计算结果以数组、表格和普通字典返回。文件读写、图形输出、进度通知集中在边界函数。
每次运行产生独立 run_id，保存已解析参数、输入文件校验摘要、版本、随机种子、软件环境、质控记录和失败原因。原数据只读；中间数据与输出放入新目录。

三 CSV 通用规范与表格模板
第一版只承诺通用 CSV，不承诺识别所有设备私有格式。提供列映射向导，将任意厂家列名映射到标准字段。映射保存 JSON，可复用；未来设备插件只负责读取和转换，不复制算法。
原始信号推荐长表字段：subject_id 被试编号；session_id 场次；recording_id 记录；time_s 相对秒；eda_uS 皮肤电导微西门子。最低要求是数值 EDA 与可靠时间轴；编号可来自导入清单。若没有 time_s，必须由用户填写采样率才能生成时间轴，不推测采样率。
可选字段：timestamp_utc 带时区绝对时间；event_code；channel；device_id；quality_flag；acc_x/acc_y/acc_z；skin_temp；condition。额外字段保留但不得自动当协变量。
信号时间和幅值字段不得在同一行全部缺失。缺失用空单元格或 NA，统一转缺失而不是零。保留真实零值；非数值、无穷值、重复时间、倒序和不规则采样必须给出诊断。
单位允许明确映射到 μS，原始电阻数据若要转换须有正确单位、非零校验与记录；未知单位不能自动假定 μS。
事件表：recording_id、event_id、onset_s、duration_s、event_type、condition；duration 可为零。重叠事件保留，不强制删除。事件响应窗口跨坏段时标记无效，不悄悄缩窗。
被试表：subject_id 必填；group、age、sex、其他协变量可选。不得把未填组别当对照组。重复 subject_id 与冲突信息须报告。
多人分组表：group_id、session_id、subject_id、recording_id、role 可选。同步对齐表：recording_id、anchor_id、local_time_s、reference_time_s。仅相同采样率和长度不能证明已同步。
导入清单：file_path、recording_id、subject_id、session_id、sampling_rate_hz、eda_unit、mapping_profile。每个模板提供字段说明、必填/可选、示例、允许值和缺失规则。
UI 对所有输入表格都有三个按钮：查看模板、下载模板、导入填写后的表格。文件/文件夹提供选择、路径显示和预览；预览只显示部分行并注明总行数，不改变文件。

四 处理流程
1 启动检测：检查核心组件、可选算法/求解器、CPU 核数、内存、可用 GPU、输出目录写入能力。可选组件缺失只禁用相应功能，不能使整个软件无法启动。
2 导入与字段映射：编码/分隔符检查、单位检查、时间轴检查、编号关联、文件预览。
3 原始质控：缺失率、有效时长、平线、突跳、异常斜率、疑似离肤/饱和、采样率波动；阈值由设备和数据决定，不设一个适用于所有人的固定正常范围。
4 坏段处理：人工标注与自动候选并存；保留原始标记、原因与编辑历史。短缺口插值可选，最大时长显式配置；长缺口不跨越插值，分段计算。
5 预处理：可选平滑、低通、重采样、基线校正。离线零相位滤波标记为非因果，不用于宣称实时处理。重采样先抗混叠，滤波不得跨长缺口。
6 分解与 SCR：选定一种主分解方法，分别输出 tonic、phasic、driver（若算法提供）及重建残差。峰值检测参数明确单位、相对/绝对阈值、最短间隔、起止点和重叠规则。
7 分窗与特征：全程、固定窗口、事件窗口、条件区间分开计算；输出有效比例和实际分母。
8 多人同步：共同时间基准、重叠有效区间、可选尺度处理、配对/群体指标和统计零模型。
9 统计与绘图：遵循被试/组/场次层级，避免把大量窗口当独立样本；输出效应量、区间、检验与多重比较记录。
10 导出：信号、特征、质控、同步矩阵、统计、图片、配置和可复现报告。

五 方法与特征目录
基础预处理：低通 Butterworth、可选中值/移动平滑、局部异常检测、短缺口线性或 PCHIP 插值、显式降采样。所有参数需通过代表性数据验证。
分解候选：滤波分离法、cvxEDA 凸优化、Ledalab CDA/DDA 相关方法、稀疏反卷积。它们不是同一个算法，不能互换标签；依赖许可证、求解器、性能和实际复现情况决定第一版可用状态。
已查到的重要实现注意：NeuroKit 当前 tonic/phasic 默认是 highpass，不是 cvxEDA；其峰检测 amplitude_min=0.1 是相对最大幅值比例而不是 0.1 μS；默认清洗 3 Hz 低通不适合直接照搬到 4 Hz 数据，必须核对奈奎斯特频率及源码条件。
连续特征：均值、中位数、标准差、四分位距、有效范围、斜率、SCL 均值/变化、phasic 积分、SCR 次数/每有效分钟频率、幅值均值/中位数、上升时间、恢复时间、面积。恢复未完成时输出缺失/截尾标记，不补成零。
事件特征：基线水平、事件后响应幅值、潜伏期、峰值、反应面积、响应/无响应、窗口有效比例。窗口长度与潜伏期范围由任务和文献决定，不能按不同条件事后挑窗。
扩展特征：功率谱、频带能量、熵/复杂度、时频特征。仅在采样率、时长、平稳性和方法依据满足时提供，标为研究性，不直接解释为压力或情绪标签。
皮电反映交感相关唤醒，不能单独可靠区分愉快/恐惧或诊断心理疾病；软件不输出无依据的压力分数或临床诊断。

六 多人同步第一版
输入必须能说明谁与谁在同一场次、设备时间如何映射到共同时间。优先事件/硬件同步锚点；只有单锚点仅估计偏移，多锚点才可估计漂移。无法证明对齐时可导出信号，但同步结果标记不可解释/未验证。
指标：零时滞 Pearson/Spearman、预设滞后区间的互相关、滑窗同步、tonic/phasic 分别同步、配对有效覆盖率；群体提供配对矩阵、边数、平均/中位同步与有效人数。高级相干、互递归、非线性同步作为可选，不直接沿用脑电相位同步定义。
禁止默认选择最大正相关且不校正搜索偏差。最大滞后/窗口/参数扫描必须进入零模型和多重比较处理。负相关保留，不擅自取绝对值。
零模型候选：保持时间自相关的循环移位或块方法、跨组重配对等；根据任务是否有共同刺激选择可解释零模型。移位最小距离、坏段、边界及有效对齐需规范，不能将任意逐点打乱作为主零模型。
同组多条边及重复窗口并非独立。推断以组/被试层级重采样、置换或混合模型为主。共同刺激、共同运动、共同趋势可造成同步，结果不直接证明交流或因果影响。

七 JSON 方案与运行接口
预设至少包括：single_standard 单人标准；single_event 单人事件相关；single_advanced 单人复杂/严格质控；group_sync 多人同步；custom 自定义。所谓高要求不表示自动堆叠更多滤波，而是更严格质控、参数溯源和验证。
方案包含 schema_version、pipeline_id、input、mapping、qc、preprocess、decomposition、scr、windows、features、synchrony、statistics、compute、output。JSON 不允许执行任意代码或动态 eval。
示例结构：
{
  "schema_version": "1.0",
  "pipeline_id": "single_standard",
  "input": {"manifest": "inputs.csv", "missing_tokens": ["", "NA"]},
  "preprocess": {"resample_hz": null, "lowpass_hz": null},
  "decomposition": {"method": "highpass", "parameters": {}},
  "synchrony": {"enabled": false},
  "compute": {"backend": "cpu", "workers": 1, "seed": 2026},
  "output": {"directory": "results", "overwrite": false}
}
该示例仅展示结构，不是经过验证的临床/科研默认参数。UI 改动与 JSON 互相同步；导入前校验字段、版本、范围与路径，未知字段明确提示，不能静默丢弃。运行前显示实际执行顺序与参数摘要。

九 UI 与帮助
左侧流程导航：项目、导入、质控、预处理、分析、多人同步、统计、结果。上方方案选择/导入/保存，右侧参数与说明，下方日志/进度/取消。
质控图同时展示原始、处理后、坏段、事件和 SCR；支持缩放定位与人工标记。任何人工修改记录操作者、时间和原因。
提供预览执行计划、单文件试跑、批量运行、失败项重试、结果目录打开。长任务使用后台任务，不阻塞界面。取消只在安全边界停止，保留已完成项并清晰区分部分完成。
帮助包含快速入门、每种方法说明、字段字典、错误排查、CPU/GPU说明。正式操作指南必须基于实际发布版本截图，依次覆盖首次启动检测、下载模板、导入、映射、选方案、质控、运行、统计、导出；截图编号与软件版本绑定。

十 性能与依赖策略
CPU 路径完整可用；默认保守进程数，避免并行任务与 BLAS 多线程叠加。优先按独立被试/记录并行，不对同一短序列盲目并行。设内存预算和任务队列，日志记录实际后端。
GPU 仅考虑长批次矩阵、重复置换或确有支持的算法；先基准测试含传输耗时，再决定是否提供。普通滤波/少量 SCR 不承诺 GPU 更快。缺 GPU 自动使用同一算法的 CPU 实现并记录；算法不等价时不得自动替换。
成熟包优先。大量使用则正常依赖包；摘取少数函数须先核许可证、传递依赖、原作者/版本/提交、修改内容和测试，不能仅按函数数量判断是否复制。不得从无明确许可的仓库直接抄代码。
候选：NumPy、SciPy、pandas、NeuroKit2、statsmodels、joblib、Matplotlib、PySide6、PyInstaller；各版本和许可证在执行前核实锁定。cvxEDA/求解器与 GUI 发行许可单独审查。当前尚未做 Windows 安装包实测。

十一 验证与验收
合成数据必须包含已知 SCR、重叠响应、缓慢基线、长短缺口、突跳、平线、低采样率及不规则时间。用合成数据验证接口和边界，不能声称替代真实数据验证。
后续至少加入不同设备/采样率/任务的合法真实数据，并与可信实现或人工标注比较。报告波形误差、事件检出、参数敏感性及失败样例，不只报告程序无报错。
GUI 与 CLI 同配置结果一致；CPU/GPU在明示容差内比较；版本、随机性、线程及求解器记录完整。无外部 Python/MATLAB 的干净 Windows 机器验证便携包启动与完整流程。尚无真实样例时，把真实性能/科学有效性标为待验，不能填通过。

十二 分阶段 Codex 执行指令
通用要求：只执行本次指定阶段。开始先读已存在代码、项目约定、上次交接与未提交变更；不覆盖用户数据；先给本阶段计划。完成交付清单、测试证据、未通过项与下一步建议后停止。未获要求不提交/推送、不安装全局服务、不启动下一阶段。
P00 需求冻结和证据核查：核对本方案、文献/源码/许可与真实数据缺口；输出需求矩阵、方法证据表、范围和待确认项。验收：每条需求有实现阶段和验证方法。
P01 架构及数据契约：定义普通字典/数组/表格结构、函数 I/O、CSV schema、JSON schema、输出目录；先交付规范与最小纯函数骨架。验收：无 GUI 依赖的核心可导入。
P02 模板和 CSV 导入：完成全部模板、列映射、NA/单位/时间校验及预览。验收：规范/混乱列名/缺失/冲突样例均有明确结果。
P03 质控与坏段：自动候选、人工编辑记录、分段和短缺口策略。验收：原数据不变，坏段可追溯。
P04 基础预处理：滤波、重采样和基线功能；验证频率边界和缺口处理。验收：每一步有数值对照和参数记录。
P05 分解和 SCR：先一个可靠默认方法，再独立接入其他方法；核求解器与许可。验收：输出成分/残差/峰事件，失败不静默。
P06 单人特征：连续/窗口/事件特征、单位和有效分母。验收：手算小样例与无响应/缺失边界正确。
P07 多人同步：时间锚点、漂移、配对与群体、零模型。验收：已知同步/无同步合成对照和依赖结构报告。
P08 统计和绘图：设计表、描述统计/适合的组内组间分析/混合模型、效应量/置信区间/FDR、出版图导出。验收：不把窗口当独立被试。
P09 CLI 和 JSON：预设、自定义、schema校验、进度/取消/失败恢复、完整溯源。验收：可重复运行且结果一致。
P10 GUI：所有页面和三个模板按钮、曲线质控、方案管理、异步任务及取消。验收：界面调用同一核心，真实操作不依赖占位数据。
P11 CPU 并行与选择性 GPU：性能剖析、基准数据、资源上限与数值一致性。验收：不满足收益的 GPU 路径不列为已支持。
P12 指南和方法文档：中文注释检查、函数指南、真实截图操作手册和内置 PDF。验收：每个功能能从界面找到帮助，截图对应实际版本。
P13 Windows 发行：锁定依赖、许可证清单、便携 EXE、构建脚本和干净系统测试。验收：无 MATLAB，发行包无需用户另装 Python；源码模式另行说明。
P14 科学验证与最终交付：真实数据对照、功能覆盖、限制清单、复现报告和维护/插件指南。验收：已验证/未验证清楚分开，不以单次成功冒充全面通过。

十四 阅读顺序与范围状态
第一至十三节为总体方案，第十五至十九节为数据契约、算法约定、输出与可复制的逐阶段任务。附录A为方法证据，附录B为多人同步，附录C为技术栈及许可。附录中的MVP/v2/v3仅指各算法的成熟度分层，绝不删除本方案已确定的首版多人同步、GUI/CLI、模板、JSON和EXE目标。
“核验”限于来源查阅；真实数据科学有效性、精确运行时间、GPU收益、Windows发行兼容性仍须后续实测。范围内不开展实时采集、实验编程或磁共振处理。

十六 算法实现层面的具体约定
质量掩码采用位标记或独立布尔列：原始缺失、自动异常、人工异常、插值、滤波边缘、不可信时间、有效。保留多个原因，不用一个好/坏标记覆盖历史。不同算法可要求不同掩码，分析有效与“已插值”不得混为一谈。
滤波按连续有效段处理：检查段长、采样频率和边界延拓需求；不满足长度时返回可诊断的跳过/失败。离线零相位算法双向滤波改变有效频响，方法说明同时写单向阶数、双向执行及参数，不只写“四阶”。对不规则采样先评估时间误差与缺口，再决定规则化，不能直接把行序号当等间隔时间。
插值只修复小缺口且记录范围；不能制造皮电反应作为真实观测。默认最大插值长度应作为设备/任务待校准参数，而不是包装成文献证明的普适常数。插值前后保留对照图，特征可选择排除含插值的窗口。
SCR 定义必须区分原始局部峰、phasic 波形峰与反卷积 driver 脉冲。每个结果表记录 signal_basis 和 method_id。连续 SCR 与事件 SCR 分开；重叠事件难以归因时标注 ambiguous，不强制把一个响应重复分给所有刺激。
反应率=合格反应数/有效分钟；有效时间为零返回 NA，不返回0。无反应但信号有效时反应次数为0，幅值均值可为 NA；另提供含零的事件反应幅值口径并明确命名，不混用。
基线校正与尺度标准化不等于消除 tonic；z 分数、个体内范围标准化、对数变换均作为独立选项。零方差时拒绝 z 分数；含负值的基线校正信号不得直接取对数。跨人原始幅值比较须说明个体和测量差异，标准化须只用预先定义的区间。
频谱与非线性特征每项附 minimum_duration、minimum_samples、input_basis、单位和可靠性条件。熵特征必须记录嵌入维度、延迟、容差、归一化及样本不足策略；不提供未经验证的“复杂度越高越好”。

十七 统计分析可执行设计
第一版至少提供描述统计、单组/配对/独立组比较、相关与线性混合效应模型的明确入口。不是让软件自动试遍方法挑最显著结果。统计设计表指明 outcome、subject_id、group_id、condition、session、covariates 与计划对比。
简单比较可调用成熟实现的 t 检验、Welch、配对检验及适当非参数方案，但选择取决于研究设计和假设。重复条件优先被试层级汇总或含被试随机截距的混合模型；模型不收敛和奇异结构必须显示，不自动删协变量后宣称成功。
输出每个检验的完整样本数、排除原因、估计量、标准误/区间、检验统计量、自由度（适用时）、原始p值、校正p值及校正家族。FDR 的家族范围需在运行前明确，例如某一特征集合或全体配对，而不是结果出来后任意划分。
EDA反应次数可偏斜/有大量零，不能无条件对所有变量套正态模型。计数/零膨胀模型先列扩展，只有在验证与诊断完善后解锁。缺失组别或协变量默认完整案例并报告损失，不自动均值填补。
同步推断把时间依赖和群体依赖分别处理：时间替代数据解决序列零模型，组/被试层级推断解决样本独立性，二者不能互相替代。保留 signed correlation，必要时仅对适用相关系数用 Fisher z 后汇总，再变换回展示。

EDA 方法研究与软件设计证据

检索日期：2026-10-25。仅采用原创研究、作者/项目官方实现。下列“建议”是拟议软件设计，不是论文确立的普适标准。年代以正式卷期为主，另注明在线年份；2026 预印本单列。未安装或运行任何 EDA 软件。

先读：影响方案正确性的结论

1. 应做“可审计、多算法、参数显式”的研究软件，不应宣传某一种分解为生理真值。Kuhn 等在两套恐惧条件化数据上比较七种量化路线，结论反对存在普适最优方法，且同名方法内部实现也存在异质性。2022 原创比较研究（https://doi.org/10.1111/psyp.14058）
2. 当前 NeuroKit 官方源码的默认分解是 highpass（0.05 Hz），并非 cvxEDA；其 amplitude_min=0.1 是相对最大幅值的比例，并非 0.1 μS。把这些默认值写错会造成实质性复现错误。分解源码（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_phasic.html） 峰检测源码（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_findpeaks.html）
3. 高通分离、反卷积 phasic SC、反卷积 driver 是不同对象，不能同列为“SCR”，更不能统一贴 μS 标签。保留 signal_domain、unit、method、normalization，每个特征必须绑定其输入信号域。
4. 2024 Kong 等 1D U-Net 伪迹检测论文已有 2026-10-15 Editor’s Note；本次只能核验到说明的书目，未取得正文，原因不明，不能说是撤稿。建议该方法列待核验研究候选，不作主推荐。原文（https://pubmed.ncbi.nlm.nih.gov/39270456/） Editor’s Note（https://pubmed.ncbi.nlm.nih.gov/42855346/），说明 DOI：10.1016/j.compbiomed.2026.111985。
5. 近期更适合进入产品方法比较面板的是 2024 fixed-plus-adaptive（FA）SCR 阈值：先固定绝对幅值筛选，再按响应幅度/该响应起点 SC 的百分比筛选；这不是 NeuroKit 的“相对于全段最大峰”。Kleckner 等（https://pubmed.ncbi.nlm.nih.gov/38104772/）

1. 质量控制、伪迹与滤波

1.1 最小必要 QC（软件设计建议）

- 导入先检查单调时间戳、重复时间、采样率与时间差不一致、单位、缺失/Inf、负值、ADC 上下限/截断、平线、跳变、掉线及事件时钟偏移；不能把异常样本简单删除后拼接时间轴。
- 原始数据只读；独立保存样本级 mask 与区间级 annotation，区分“无效”“疑似”“人工确认”“插值”“滤波边界”。同一位置允许多个原因。
- 加速度、皮温只作为辅助证据；运动不必然等于伪迹，皮温阈值需按佩戴部位、硬件和环境校准。无温度通道时显示“未评估”，不能当作通过。
- 先定位并标注伪迹，再对有效连续段处理；低通只能抑制部分噪声，不保证去除接触变化/运动伪迹。
- 默认不自动补长缺口。短缺口可配置线性插值上限、邻域保护，并保留原 mask；跨缺口 SCR 不作完整事件；严重污染试次输出缺失原因，不能作为零反应。
- 图形审阅联动 raw、clean、tonic、phasic、driver、峰起点/峰值/恢复点、事件与 QC；支持撤销、版本化人工修订、自动与人工结果并存。

1.2 已验证方法与边界

Kleckner EDAQA（2018，2017 在线）：四类透明规则为 SC 越界、变化过快、皮温提示未佩戴、污染边界过渡段。原研究 Q Sensor 腕部数据的例值：0.05–60 μS，±10 μS/s，30–40°C，污染邻域 5 s。来自20名儿童、181小时记录，并与专家判断比较；不是其他设备/人群的正常生理范围。软件宜提供“复现原研究”预设，不以此永久删除数据。原研究及验证（https://pubmed.ncbi.nlm.nih.gov/28976309/） 作者论文 PDF（https://affective-science.org/wp-content/uploads/2024/03/Kleckner_Quigley_et-al_2018_Simple_Transparent_and_Flexible_Automated_Quality_Assessment_Procedures_for_Ambulatory_Electrodermal_Activity_Data.pdf）

Taylor/EDA Explorer（2015）：基于原始/滤波信号导数和 Haar 小波特征的 SVM 分类；官方实现用 8 Hz 数据、5 s 窗，支持二分类或 artifact/questionable/clean。适合作为历史可比基线；旧依赖、采样率假设和目标设备迁移必须独立检验。检测标签不是“纠正后的真实信号”。论文（https://pubmed.ncbi.nlm.nih.gov/26736662/） 官方仓库（https://github.com/MITMediaLabAffectiveComputing/eda-explorer） 实际特征与窗口源码（https://raw.githubusercontent.com/MITMediaLabAffectiveComputing/eda-explorer/master/EDA-Artifact-Detection-Script.py）

Kong 等（2022）：有同步参考 EDA 的伪迹标注数据库与机器学习检测，并在独立数据检验泛化；报告94.7%准确率，但不应与不同数据集的 balanced accuracy 直接排名。原创论文（https://doi.org/10.1016/j.bspc.2022.103483）

Pattyn 等（2023）：在200小时模拟行走日常型 EDA、0.125–3个伪迹/分钟条件下比较保留、剔除及插值。不同指标得出不同结论：插值对某些 phasic 特征有益，不等于所有 SCR 检测或 tonic 指标都改善。不能据此允许任意长缺口补全。原创研究（https://pubmed.ncbi.nlm.nih.gov/37863009/）

Kong 等（2024，附2026说明）：频谱图 + 1D U-Net，104名受试者/四数据集/两个独立测试集，独立测试 balanced accuracy 为80.0±13.7%和75.0±14.0%，而不是笼统95%可靠性。部署候选仅在核验2026 Editor’s Note后再评估。原创摘要（https://pubmed.ncbi.nlm.nih.gov/39270456/） 说明记录（https://pubmed.ncbi.nlm.nih.gov/42855346/）

1.3 滤波与重采样

- NeuroKit兼容预设：3 Hz、四阶Butterworth；官方源码在 fs≤6 Hz 时跳过该滤波。BioSPPy兼容预设：5 Hz四阶Butterworth，另有0.75 s平滑。因此4 Hz数据绝不能直接套3/5 Hz低通。官方清洗源码（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_clean.html）
- 建议把采样率、截止频率、阶数、因果/零相位、边界填充、段长限制、抗混叠策略全部写入配置和报告。降采样先抗混叠；升采样不增加生理时间分辨率。
- 离线零相位与在线因果滤波分成不同 pipeline，不能声称输出完全一致。对每种原始采样率验证 SCR 幅值/时延偏差。
- 官方 NeuroKit 清洗会对NaN作前向填充。建议不直接采用此缺失策略：软件先管理缺口，避免把长失联伪装为平稳观测。

2. tonic/phasic 分解目录

A. 高通/低通基线（MVP候选）

当前 NeuroKit highpass 用0.05 Hz高通提取 phasic，并另做低通估计 tonic；smoothmedian 以4 s中值平滑估计 tonic，再相减。优点是快速透明、适合可视化基线；缺点是频率分离不等于神经驱动反演，截止/平滑窗口改变形态，phasic可负值。4 s和0.05 Hz仅为具体实现默认值。官方源码（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_phasic.html）

建议：方法选择器明确标“滤波分离”；验证两路独立滤波的重构误差，不默认假设 tonic+phasic 精确等于输入。此路线用于快速结果和其他模型的对照，不称“最准确”。

B. cvxEDA（2016；2015在线，研究主力候选）

模型为 phasic + tonic + 残差，使用 Bateman 动力学、非负稀疏 driver、平滑样条 tonic 和凸优化；输出应保留 phasic、driver、tonic、residual、objective、求解状态。原论文验证涉及噪声、刺激辨别与情感刺激，不等于跨设备绝对真值。论文（https://repository.essex.ac.uk/14731/1/Greco2015cvxEDA.pdf） 作者官方仓库（https://github.com/lciti/cvxEDA）

作者实现默认 tau0=2 s、tau1=0.7 s、knot间距10 s、alpha=8e-4、gamma=1e-2；推荐输入z-score。2025代码更新了边界与基线选项，故必须固定版本/commit；不能假定NeuroKit内嵌实现和作者最新版相同。GPL-3.0，分发前以选定版本许可证确认兼容性；CVXOPT另为GPL-3.0-or-later。作者源码（https://raw.githubusercontent.com/lciti/cvxEDA/main/python/cvxeda/cvxEDA.py）

建议：这些参数提供“作者复现预设”，用pilot做敏感性检查；保留输入均值/标准差，输出若未反变换则标标准化单位。恢复到原SC单位时 phasic与residual乘标准差，tonic乘标准差后加均值，并验证重构；driver单位另按核归一化和离散化定义，不能照抄phasic单位。凸问题全局最优不代表生理真值；异常伪迹并不服从高斯残差假设。

C. Ledalab CDA（2010）

标准反卷积、个体化响应函数参数、tonic估计，得到连续 phasic driver；可计算时间窗积分，降低重叠响应对简单峰值计分的影响。CDA driver允许负值，可能反映模型不匹配或伪迹；不能把负值统一截为0而不记录。原创论文（https://pmc.ncbi.nlm.nih.gov/articles/PMC2892750/）

软件保留与命名：phasic conductance与phasic driver分开；CDA.SCR是窗口内driver均值，CDA.ISCR是driver积分，不是一般的峰高或AmpSum。官方输出定义（https://github.com/ledalab/ledalab/wiki/Results）

D. Ledalab DDA（2010）

非负反卷积得到离散紧凑响应，并用额外余项描述偏离标准SCR形态的部分。强调单响应重构和参数，不同于CDA连续driver。其汗孔解释是模型假设，不能直接报告为实测汗孔活动。原创论文（https://pubmed.ncbi.nlm.nih.gov/20230512/） 官方代码（https://github.com/ledalab/ledalab）

建议：初期以官方MATLAB导入/导出及固定样例交叉验证实现互操作；未建立数值等价前，不给自写Python版本贴“Ledalab完全兼容”。

E. SparsEDA（2018；2017在线）

非负稀疏反卷积、过完备多尺度字典、联合恢复SCL及稀疏driver；原研究含100名不同受试者，适合长时连续处理的候选。须看实际实现而非只引用摘要的“任意长度”：作者代码内部70 s分析段，短于80 s会警告，fs>8 Hz时降至8 Hz。原创论文（https://pubmed.ncbi.nlm.nih.gov/29990244/） 作者源码（https://github.com/fhernandogallego/sparsEDA/blob/master/sparsEDA.m）

建议：v2研究扩展；检查稀疏化导致漏小峰、块边界和重采样偏差。NeuroKit文档自己提醒其移植仍需核查及存在不明报错，不能默认视为作者实现等价。NeuroKit实现警告（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_phasic.html）

F. PsPM GLM/DCM（2009起，事件研究扩展）

GLM将事件设计与canonical SCR响应函数卷积，估计条件/试次效应，绕开逐峰计分；适合事件较密且设计明确的数据。DCM用于更复杂的预期性或自发活动。它们不是通用峰检测器，回归系数/潜变量不与μS峰幅直接混合。2009原创（https://pubmed.ncbi.nlm.nih.gov/19686778/） 官方文档（https://bachlab.github.io/PsPM/documentation/） 官方仓库（https://github.com/bachlab/pspm）

建议：v2/v3插件，需事件设计矩阵、共线性与残差诊断，支持导出而非MVP重写全套模型。

3. 2020–2026 新方法与证据分层

- 2020，van Halem等：82名年轻成人、5天日常采样中，依据SC相对上升触发并未得到更多心理高唤醒情境。对产品最重要的启示是“皮导上升≠用户正在焦虑/压力大”。原创作者存档（https://research.tilburguniversity.edu/en/publications/moments-that-matter-on-the-complexity-of-using-triggers-based-on-/），DOI 10.1002/per.2252。
- 2021，Amin/Faghih 生理先验稀疏分解：二阶动力学 + tonic B样条；生理先验、稀疏/平滑约束与广义交叉验证坐标下降，自动平衡各惩罚。作为个体参数与调参策略扩展，不凭拟合度认定神经driver正确。原创（https://pubmed.ncbi.nlm.nih.gov/33119508/），DOI 10.1109/TBME.2020.3034632。
- 2021，NeuroKit2工具论文：是工程编排/方法对照的重要参考，而非“每一默认路径均已在所有数据验证”的保证。作者论文（https://realitybending.github.io/publication/makowski2021neurokit/makowski2021neurokit.pdf），DOI 10.3758/s13428-020-01516-y。
- 2022，Amin/Faghih BayesianEDA：3维生理状态空间模型，结合固定区间平滑稀疏恢复、GCV与EM估参；26人听觉刺激数据。面向可扩展、近实时研究，但fixed-interval smoother仍可能依赖未来样本，不能直接称零延迟流处理。原创全文（https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1010275） 论文指定代码（https://github.com/computational-medicine-lab/BayesianEDA-For-Sharing）
- 2022，Kuhn等方法多重比较：两数据集、七种SCR量化，无普适赢家。产品应保留选择依据、敏感性比较、分析前锁定参数，避免按显著性选择算法。原创（https://doi.org/10.1111/psyp.14058）
- 2023，Pattyn等模拟伪迹研究：给出带可控伪迹的评估思路，支持“波形、峰、特征、下游任务”多层验证，而不只看曲线平滑。原创（https://pubmed.ncbi.nlm.nih.gov/37863009/）
- 2024，Kleckner等FA阈值：254名成人实验室数据及20名儿童临床场景；绝对初筛>0.01 μS，再按RAP=幅值/起点SC筛选。研究测试1.9%，讨论对相似日常情境3.3%，作者明确要求新任务/人群独立pilot与泛化验证；效应提升是温和的，不能写“全面优于传统阈值”。建议v2比较模式，而非默认替换固定阈值。原创（https://pubmed.ncbi.nlm.nih.gov/38104772/） 全文（https://pmc.ncbi.nlm.nih.gov/articles/PMC10872538/），DOI 10.1016/j.ijpsycho.2023.112280。
- 2024，1D U-Net QC：上文列出，2026新增Editor’s Note状态必须附注。
- 2025，Wang/Marsella/Pavel统一动态模型（2024在线）：四阶LTI统一tonic/phasic，系统辨识与稀疏优化，超过200人数据；三分量表示。作为研究分支；高重构R²不是潜在神经信号的直接真值验证。正式摘要（https://pubmed.ncbi.nlm.nih.gov/39499611/） 作者预印本（https://arxiv.org/abs/2311.02799），DOI 10.1109/TBME.2024.3492112。
- 2025，Feel Transformer：改造Autoformer、无显式分解标签；40人16周真实世界数据，比较分解与特征分布，明确面临无统一ground truth问题。双向非自回归重构不等于真实在线因果检测，也不能证明心理健康诊断有效。建议v3实验插件，需额外训练数据、权重/许可证、跨设备独立测试。原创（https://www.mdpi.com/1424-8220/25/14/4406），DOI 10.3390/s25144406。
- 2026，gmsEDA（8月13日预印本）：广义矩阵分离、联合处理多条记录，模拟与真实数据比较。属于前沿候选，不作为成熟默认；跨受试者联合分解要检查训练/测试泄漏和单记录可用性。作者预印本（https://arxiv.org/abs/2608.14732）
- 2026，Chai等（10月5日预印本）：VR平衡任务中校正降低波形误差但未改善下游分类，且减少SCR检测。只可作为“必须保留未校正对照臂”的新证据，不能泛化为“伪迹不用处理”。作者预印本（https://arxiv.org/abs/2610.07438）

4. SCR检测和特征定义合同

4.1 检测方法

- Trough-to-peak：明确输入是raw/clean/分解phasic，onset如何定义，幅度=peak−onset；重叠时可能低估后续响应。
- NeuroKit：relative-height检测；Kim/BioSPPy：导数、Bartlett平滑、零交叉；Gamboa：局部极值；van Halem实现：持续上升/下降0.5 s条件；Nabian实现：导数零交叉及相对幅度规则。官方各方法源码（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_findpeaks.html）
- 不建议MVP向用户平铺所有方法作为等效按钮；先TTP显式绝对阈值与一个可靠分解路线，其他放比较页。固定样本数窗口（如Savitzky–Golay 501样本）需审计，换采样率后不应误称相同时间尺度。
- 阈值建议：提供0.01/0.03/0.05 μS的研究兼容模板，首次必须确认单位/设备分辨率；固定、相对最大峰、FA相对onset三类在UI明确区分。选定值只是研究方案设置，不是“生理SCR的唯一标准”。

4.2 每个SCR事件建议输出

scr_id, onset_time_s, peak_time_s, recovery_time_s, amplitude_uS, peak_height_uS, rise_time_s, half_recovery_duration_s, area_uS_s, method, signal_domain, threshold_type, threshold_value, qc_status, censored_reason。

数学语义：rise_time=peak−onset；恢复时间从peak到指定幅度比例的首次有效下降交点；未观察到恢复、遇下个峰/缺口/边界是删失或NA，不是0。peak height与onset-to-peak amplitude分开。NeuroKit官方实现亦按onset差定义幅值、按秒定义上升与恢复。源码（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_peaks.html）

4.3 事件相关输出

- 每事件保留baseline窗、响应起始窗、峰搜索窗、恢复观察窗及事件重叠标志；明确以onset还是peak归属窗口。建议预设例：baseline −2至0 s、起始1至4 s、更长峰/恢复观察区，但必须按刺激/范式定制，非通用标准。
- 输出response_present、nSCR、first/maximum amplitude（名称区分）、latency、AmpSum、phasic导电积分、driver积分、tonic均值、有效数据占比。
- “无响应”有效试次可按明确规则记幅值0；污染/事件缺失/窗口不足为NA。报告计数分母与排除原因。不能把NK事件函数只取第一个SCR，误解为窗口最大或AmpSum。NK事件实现（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_eventrelated.html）
- Ledalab CDA.SCR（driver均值，μS）与CDA.ISCR（driver积分，μS·s）不同；AmpSum（μS）来自重构响应。官方wiki的DDA.AreaSum单位标注可疑，建议核查实现与量纲后标记，不照抄。官方字段（https://github.com/ledalab/ledalab/wiki/Results）

4.4 连续窗口输出

- SC/tonic均值、中位数、SD、IQR（μS），tonic斜率（μS/s），SCR数（个）、率（个/有效分钟），幅值均值/中位数/总和（μS），phasic AUC（μS·s），有效占比、插值占比、伪迹占比。
- 建议基础窗口60 s/步长30 s可配置；对比条件和下游建模应报告重叠，按受试者/会话分组划分，避免重叠窗口泄漏。
- 频域研究扩展：PSD单位 μS²/Hz，积分功率 μS²，归一化功率注明分母。Posada-Quintero 2016研究的EDA sympathetic频带0.045–0.25 Hz与TVSymp的0.08–0.24 Hz不可混为同一算法。PSD原创（https://pubmed.ncbi.nlm.nih.gov/27059225/） TVSymp原创（https://pubmed.ncbi.nlm.nih.gov/27440716/）
- NK interval实现只在>64 s计算其Posada指数，短窗不能机械输出该特征。其sympathetic源码的归一化说明和实际按最大PSD归一化存在不一致，须固定公式，不可仅靠字段名认为是“除总功率”。interval源码（https://neuropsychology.github.io/NeuroKit/_modules/neurokit2/eda/eda_intervalrelated.html） sympathetic源码（https://raw.githubusercontent.com/neuropsychology/NeuroKit/master/neurokit2/eda/eda_sympathetic.py）
- 熵、DFA、分形、时频、网络特征可放实验层；要求最小有效长度、参数、稳定性分析，不在首版默认生成大量难解释特征。

5. 验证与验收设计建议

五层验证，不能只比较波形

1. 数据正确性：导入单位、时间戳、事件同步、resample索引往返、缺口和人工标注保持；μS↔S、秒↔样本可回溯。
2. 数值复现：固定算法版本、依赖、参数、随机种子，用作者示例与官方输出作黄金样本；报告绝对/相对误差、边界区误差、残差和solver失败。是实现复现，不是生理真值。
3. 受控仿真：已知tonic/driver/SCR核，改变响应重叠、形态、噪声、采样率、缺口、尖峰、台阶和饱和；不可只用和待测模型完全相同的生成模型。峰precision/recall/F1配明确匹配容忍窗，幅值/时延/积分误差，分解RMSE与形态偏差。
4. 真实专家标注：至少两名独立标注者、盲法、共识/不一致记录；分开报告检测器对伪迹、对SCR和非响应判断的表现，按设备/部位/人群分层。人工“clean”也非神经driver真值。
5. 目标研究效用：预注册效应、条件差、test–retest/ICC、跨被试/跨设备泛化；保留raw/no-correction臂，比较清洗后是否损失真实SCR。ML调参只在训练集/嵌套验证完成，不能用测试集选滤波/阈值/分解。

建议测试边界

空文件、全NaN、常数/近常数（z-score除0）、短于padding、首尾峰、无峰、重叠峰、恢复未完成、非整数采样率、4 Hz低采样、时间倒退、重复采样、分段边界、长掉线、极大跳变、混合单位、事件落在缺口、多个事件竞争同一SCR。

候选工程验收门槛应待pilot确定

可先把“无静默失败；所有特征含单位/质量状态；缺口不伪装为零；100%运行可追溯；无峰输出合法空表；人工编辑可撤销”作为硬门槛。峰F1、幅值误差、运行速度和可用率阈值应按设备、样本和用途制定，不从单篇论文搬来承诺。

6. 建议版本划分

- MVP：导入与单位/时间校验、raw不可变、QC规则与人工复核、显式滤波预设、highpass基线 + cvxEDA可选适配、TTP绝对阈值、事件/连续特征、图形审阅、批处理、方法配置和完整导出。
- v2：Ledalab互操作与数值复现、SparsEDA、FA阈值、多算法敏感性报告、PsPM事件模型导出/接口、频域与公开基准评估。
- v3：BayesianEDA、统一动态模型、Transformer/gmsEDA等研究插件、在线因果链路、跨设备训练与独立验证。前沿预印本须显式标记，不能覆盖稳定默认。

多人 EDA 同步：V1 方法、统计与验证规划

研究核查日期：2026-10-25。以下是规划建议，不是已经实现或经过验证的软件。论文参数仅作可复现参照，不能当作跨设备、跨任务的统一标准。本文以原始研究、方法论文和官方工具文档为主；没有安装软件或运行算法。

1. 最重要的产品决定

V1 应是“可审计的多人 EDA 分析工作台”，而不是“一键默契/情绪评分器”。优先完成时间轴与质量控制、带符号的两两同步、合适的零假设、群体描述、可重现导出。新增复杂算法不应优先于防止伪同步。

必须区分三个问题：

1. 同一时刻的 EDA 是否共同变化？这是描述性时间对应。
2. 这种对应是否超过各自慢变和自相关能够产生的程度？需要时间替代数据。
3. 这种对应是否超出共同刺激、共同任务和动作造成的程度，并且是否特属于实际互动伙伴？需要设计匹配的伪配对、对照条件或协变量，不能靠时间错位替代数据单独解决。

相关、反相关、共同唤醒、预测性先后、心理共情是不同概念。软件不得将正相关标成“共情”，负相关标成“冲突”，高值标成“关系好”，也不得将滞后峰直接标成因果领导关系。2026 年信任互惠实验的原始研究报告，同步与较低互惠的关联依赖面对面情境，进一步反对“越同步越好”的通用解释。[R9]

2. 同步前的工程门槛

2.1 时间信息必须成为一级数据

每位参与者至少保存：participant_id、group_id、session_id、device_id、原始采样率、单位、原始时间戳及其时钟域、开始时刻、采样序号、事件标记、掉样/重连记录、同步锚点和时钟校正版本。不能只保留“共同 CSV 行号”。

时钟校正分层：

- 优先同一采集系统/硬件触发，或者经实测验证的 LSL/XDF 流程。
- 多设备导入：先识别时钟 offset，再用会话前后及中途锚点估计 drift。可用 t_ref = a + b × t_device 的线性映射；重连或明显非线性漂移时分段。只有一个锚点时只能识别偏移，不能可靠估计漂移。
- 保存校正前后锚点残差、漂移 ppm、估计不确定度和校正区间，禁止静默拉伸。
- 不应通过最大化两个人的 EDA 相关性来估计设备时间偏移，这会把拟证明的同步当成校准目标，产生循环推理。
- 方向性解释必须受到同步误差限制。若估计先后差与计时不确定度相当，显示“先后关系不可分辨”，而非给出确定方向。

LSL 官方文档说明：原始时间戳和周期性 clock offsets 可写入 XDF；导入时可拟合时钟映射，规则采样流可在中断处分段处理 jitter。LSL 本身不能替未知设备内部延迟背书，也不意味着任意蓝牙设备天然拥有亚毫秒端到端精度。[T1]

2.2 重采样、缺失和有效覆盖

- 在清楚的共同参考时间轴上重采样，先抗混叠再降采样，保留原始数据。目标频率取决于原始设备与最终带宽，不把 4 Hz、8 Hz 或 10 Hz 写成唯一标准。
- 仅对明确短缺口允许可配置插值，并保留 interpolated 标记；长缺口、脱落、饱和、平直段和质量差区间保持缺失。
- 不把各自缺失数据删掉后再按行配对，不能将数分钟断档两端接成连续信号，也不能补零或无限前向填充。
- 每一窗口/滞后记录共同有效样本数、有效时长、缺失比例、插值比例、运动/质量标记。两条序列均须有足够方差；否则结果是“不可估计”，不是 0。
- “共同有效比例至少 80%”可作为待验证的工程初始值，明确可配置，不宣称生理学标准。还应约束最长连续缺口和最短连续有效段；样本数多不代表独立信息多。
- 不同 dyad 的有效覆盖若不同，群体均值可能变成时间覆盖差异。提供共同完整窗口分析和配对可用窗口分析两套敏感性结果，并显示实际纳入的参与者和边数。
- 生理分量与质量流程先于同步：cleaned EDA、tonic、phasic/driver 分别命名和计算，不混为一个同步指标；平滑、去趋势和分解版本必须进入 provenance。

3. V1 的指标分层

3.1 默认主干：窗口化、带符号的两两相关

保留三个层次的输出：整段 r（仅描述），每窗 lag=0 的 r，以及 window × lag 的完整相关曲面。主分析可用 Pearson，Spearman 作为稳健敏感性分析，不能报告两个之中较显著的那个。

建议演示预设：30 秒窗、1 秒步进、±5 秒滞后；再用 20/30/60 秒窗和不同预先指定 lag 范围做敏感性检查。这只是待设备和任务确认后的起点。2025 EDA 原始研究用 30 秒分段、±5 秒和 SUSY；2020 互动实验则用 8 秒窗，说明不存在统一“最佳窗口”。[R1, R7]

实施定义需锁定：

- 例如 r_AB(τ) = corr(A(t), B(t+τ))；正 τ 表示 A 的变化在这一数学约定下先于 B。用已知延迟的合成信号检查，而不能照抄某个库的 lag 符号。
- 不将负值取绝对值后仍称“正向同步”。signed r、absolute coupling 和反向对应分开展示，避免平均相互抵消也避免绝对值抹去意义。
- 窗口聚合可提供 Fisher z 后平均再反变换，须处理 |r|≈1 的数值边界；这只是聚合尺度，不自动获得独立窗口的标准误。
- 不同时把“平均全部 lag 的 r”“最大正相关”“最大 |r|”和“lag=0 r”称为同一指标。每种定义对应不同 estimand。
- 若探索最大峰，替代数据必须重复同样的找峰过程，检验 max-lag statistic；不能挑最高 r 再用单一相关的 p 值。
- 重叠窗口用于可视化，不可当成大量独立重复实验。

窗口分析经典依据是 Boker et al. (2002)。2022 原始方法比较发现，不同同步算法不必收敛，因此 V1 不宜加权融合成未验证的“综合同步分”。该方法比较对象为运动而非 EDA，应用到 EDA 时应明确是方法学警示而非 EDA 的直接验证。[R10, R11]

3.2 群体层：保留结构，不用总分掩盖异质性

V1 必须提供：

- 每条件/每阶段 N×N 对称相关矩阵，负值、不可估计和未检验用不同编码；对角线不参与群体统计。
- 全体有效 dyad 的 Fisher-z 平均/中位数和分布、正负对应的比例、有效成员数、有效边数和覆盖时长。
- 每个人与其余成员的平均对应或 leave-one-out 群体均值相关。排除本人，防止 part–whole 自相关。
- 群体时间曲线和 dyad 热图；若成员在不同窗口退出，明确标出组成变化，防止“同步变化”实际是参与者组成变化。
- 网络图只作为描述，边的阈值和多重校正必须说明。不同缺失掩码得到的两两相关矩阵不保证半正定，不可不检查便送进依赖 PSD 的 PCA/网络模型。

将以上命名为“组内两两同步摘要”，而不是“高阶群体耦合”。三人决策原始研究对个体贡献、双人平均、群体级 recurrence 的关联结论并不相同。[R2]

V1.1 才考虑 mvSUSY 或 MdRQA：必须在固定成员、固定质量规则和经过仿真检验的段落上，与两两摘要并列报告，而不是直接替代。mvSUSY 原始方法论文用白噪声、趋势、自相关、振荡和多变量相关等模拟与行为数据验证；这不是对所有 EDA 条件的现成验证。[R3]

3.3 CRQA 作为高级扩展

CRQA 可表达跨序列状态复现，提供 RR、DET、LAM、对角线长度、窗口 recurrence profile 等；适合研究者有明确动态问题时使用。2024 nocebo 原始研究确实对 EDA 应用 CRQA，并报告其标准化、重采样、嵌入参数和 DET/LAM，说明它是可参考的实际路线，不表示该研究参数可直接成为默认值。[R6]

必须暴露 delay、embedding dimension、radius/target RR、最短线长、标准化、窗口和边界定义；参数由训练/先导数据或预设规则决定。不同条件不能各自调到“结果最好”。如果固定 RR，不能再把 RR 当作独立结果；DET/LAM 会随半径、采样率和平滑改变。平直段会产生高 recurrence，需先剔除。计算与内存随长度增长，整小时高采样原始信号不宜直接构造完整递归矩阵。可将 R crqa 作为回归验证参照。[T3]

3.4 coherence / wavelet 不作为 V1 主指标

EDA 不是默认具有稳定相位的窄带振子。慢漂移、强自相关、共同任务节律和过度平滑都可能造成高 coherence。若未来纳入，应报告频段依据、足够周期数、窗长、谱平滑和有效自由度；wavelet 需遮蔽 cone of influence，区分共同功率与 coherence，并做保留谱结构的零假设和时间×频率多重控制。相位箭头不是因果证据。经典 wavelet 方法本身也强调机制依据及反对无差别扫描。[R14]

DTW、transfer entropy、Granger/DSEM 暂不进入默认主线。DTW 的时间弯曲可把非同时事件对齐；若用作设备校正或“真正实时同步”会产生概念错位。方向性统计若未来提供，必须控制自身惯性、采样和模型选择，不等同因果影响。

4. 零假设必须随问题选择

4.1 可用替代方法与它们实际保留的东西

1. 连续段内循环移位：保留单人序列形状和循环意义的自相关，破坏两人原有对时；适用于足够长、近似平稳的同一任务段。排除很小移位，避免保留原耦合，并处理 wrap 接缝。不能跨条件、跨长缺失或明显状态转换任意旋转。不会自动控制共同刺激。
2. block shuffle / SUSY 式 segment shuffle：保留块内时间结构，但破坏块间结构并引入边界。块长必须足以涵盖相关时间尺度，且需敏感性检查；不能说它“完整保留自相关”。适合作为文献对照方法。[R7, T2]
3. phase-randomized / IAAFT：平稳近似下保留谱/自相关结构，IAAFT 还近似匹配振幅分布；需检查收敛及谱误差。这不是无条件有效的缺失/非平稳 EDA 万能零模型。经典 IAAFT 原始论文提供方法依据。[R12]
4. 同条件、同刺激时间线的跨会话伪 dyad：保留对共同刺激的反应，破坏真实互动伙伴关系，更直接对应“实际伙伴是否超出共同任务效应”。须确保 trial 对齐、条件匹配和被试交换性，不可跨年龄组/任务/设备随意配对。
5. 条件标签置换或组级 bootstrap：用于跨条件/群组效应，按实验随机化及独立采样单元进行。它和单段时间替代检验回答不同问题。

“打乱每个采样点”破坏自相关，会产生不合理地容易拒绝的零假设，不作正式默认。建议 V1 至少支持一种时间结构保留的替代方法和一种有设计元数据支持的匹配伪配对方法。

4.2 检验实现约束

- 把 observed statistic、null definition、替代算法、有效替代次数 B、random seed 和边界处理一同导出。
- Monte Carlo 随机置换的 p 用 (1 + 更极端替代数)/(B + 1) 的适用构造，不允许 p=0；同时说明最小可分辨 p 为 1/(B+1)。1000 次左右只能作交互预览，最终 B 要依据检验族与所需尾部精度规划，不保证 999/9999 对所有研究足够。[R13]
- 缺失掩码不能与信号脱离。优先在足够长、共同有效连续段上检验；若移位带掩码，规定覆盖匹配与有效替代接受规则，防止 observed 与 surrogate 因覆盖不同而不可比。
- 对多人数据，每次替代应从“参与者序列”层统一生成，再计算所有边及群体统计，不要为每条边独立生成不一致的伪世界。
- 标准化 surrogate effect = (T_obs − mean(T_null))/sd(T_null) 可以提供，但它不等于高斯 z 检验；分母为零时应不可估计，不伪造无穷大显著性。
- 如果搜索所有窗口/lag 后只报告最高值，null 也要复制搜索与选择。单窗检验、整段聚合检验、最大统计检验须分别命名。

5. 统计独立性、多重比较与解释

5.1 样本量单位

10 个人产生 45 条 dyad 边，但不是 45 个独立社会单元；同一人出现在多条边，同一组共享任务。重叠窗口、重复 session、同一 therapist 对多个 participant 进一步形成依赖。

- V1 的正式条件比较优先先得到每 session/group 的预设摘要，再以独立 group/session 的实验结构分析。
- 保留 dyad 层时，混合效应模型要考虑 group、session、dyad 及重复出现的两位 participant。无向 dyad 的成员效应应以对称的多重成员/合适社会关系模型处理，不能随意把 ID 较小者作为“actor”后用不对称模型。
- 对直接建模时间序列，考虑趋势、个体内中心化、滞后自身项和残差序列相关；AR(1) 是可检验模型而非自动正确。Qaiser et al. 2023 是使用 dyadic mixed model 和 AR(1) 处理 SCL 等生理序列的直接原始研究例子。[R5]
- bootstrap 和置换以实验设计允许的独立 unit 为单位；不能 resample 采样点或把全部窗口当独立记录。
- 只有一个群体时，能回答该记录在指定零模型下的时间对应，不能估计一般人群中的团队效应。

5.2 多重比较

预先定义检验族：participant pairs × conditions × components × metrics，必要时还包括 windows/frequencies；探索可视化不必每像素显示未经控制的星号。

V1 支持 raw p 和校正后 p/q，同时记录 correction scope。BH-FDR 需符合相应独立/正依赖条件；任意依赖可考虑保守的 BY，或设计有效的 max-statistic/cluster permutation。FDR 不能修复错误零模型和伪重复。不要默认对每个窗口分别 BH 后宣称整个会话已控制错误发现率。[T4]

5.3 共同刺激和动作不是附注

必须可导入事件、刺激 ID、condition、说话/静默、角色、加速度/运动质量和环境记录。对同一视频、提示音、任务进程造成的同步，应使用刺激匹配伪 dyad 或合适对照；仅错位时间的零模型把刺激锁定反应也当作效应。

Golland et al. (2015) 是区分共同刺激与共在的重要原始实验参照。Tourunen et al. (2022) 的四人治疗数据研究同时考虑 EDA、运动及说话，显示模态关系随角色不同，不能简单假定 EDA 同步全是动作或完全独立于动作。[R4, R8]

协变量回归不能魔法消除未测混杂。将刺激共同成分回归掉也可能移除研究真正关心的共同反应，必须先决定问题是“共同体验”还是“伙伴特异互动”。报告原始对应、调整后对应和局限，不把其中一个叫唯一真值。

6. 导出与验收建议

最小结果长表：run_id、group/session/epoch、participant_i/j、signal_component、metric、window_start/end、lag_s、r/T、valid_n/duration、coverage、quality_status、null_method、B、p_raw、p_adjusted、correction_family、seed、config_hash。

一份报告应同时含：数据质量/排除清单、时间对齐诊断、原始与分量时间图、相关矩阵、window×lag 图、observed vs surrogate 分布、群体组成及有效覆盖、参数敏感性、可复现配置和版本。探索结果、主分析和敏感性分析分开。

先写验证计划，再写生产代码。建议用独立白噪声/AR(1)、共同慢趋势、仅共同刺激、已知正负耦合、已知 delay、时间变化耦合、时钟 offset/drift、短长缺口、平直/饱和/动作伪迹、不同采样率的合成样例建立测试集。

验收应检查：

- lag 符号、秒/采样点转换和对时残差正确；已知时钟漂移可恢复，未知漂移不伪装已解决。
- 独立但强自相关信号的拒绝率在所选零模型仿真下接近标称水平，给出 Monte Carlo 二项置信区间而非凭一例判断。
- common-stimulus-only 数据会在时间移位检验中可能显著，但不应被伙伴特异伪配对检验解释为互动证据。
- 掉样和低方差返回清楚的不可估计原因；任意数据长度、窗口边界与重连不产生静默拼接。
- 显著性完整重复峰选择、多重比较和群体聚合流程。
- 固定版本和 seed 重跑一致；对 selected cases 与 SUSY/crqa 官方输出比对，在相同参数定义下解释差异。

Windows EDA 软件：技术栈、兼容性与许可核验

核验日期：2026-10-25。范围：官方文档、官方源码、PyPI 发布元数据的静态核验；没有安装依赖、运行候选软件、执行算法或构建 EXE。下文的“可选/候选”不是“已通过 Windows 集成测试”。这是一份工程选型建议，不是法律意见。

先给结论

1. 采用“过程式数值核心 + 很薄的 PySide6 界面 + 同一核心的 CLI”是合理路线。核心只接收数组、表格、普通配置字典和路径，不依赖 Qt，也不自定义业务类；GUI 可以组合现成 Qt 对象并连接普通函数回调，不要求为业务逻辑建立类层次。
2. Python 3.12 x64 有充分的候选包元数据和 wheel 支持，但已进入仅安全维护。其最新安全版本不再提供官方 Windows 二进制安装器，必须解决已修补运行时的可信来源/构建和维护，而不是为了安装方便长期停留在旧二进制版本。建议把 Python 3.14 作为新产品的发布验证候选，3.12 仅作为兼容备选；本次针对 3.12 的逐包 wheel 核验不能代替 3.14 的完整解析、wheel 与回归测试。
3. 不要使用“所有包各取最新版”的配方：NeuroKit2 0.2.13 明确要求 pandas<3.0.0，但目前 pandas 页面已是 3.1.0。应先按约束求解，再锁定全量版本并做回归测试。
4. 默认 CPU 版，不强制 CUDA；cvxEDA/CVXOPT 与 GPU 后端均为单独评估项。cvxEDA 原实现是 GPL-3.0，CVXOPT 是 GPL-3.0-or-later，不能因为仅复制一两个函数、改名或放进插件就自动消除许可问题。
5. Windows 首先交付 one-folder EXE。它仍包含 Python 解释器，只是不要求终端用户另装 Python；采用纯 Python/SciPy 路径，不调用 MATLAB Engine，因此不需要终端用户安装 MATLAB。one-file 放到稳定后的第二阶段。

3. NeuroKit2：完整复用优先，不轻率摘函数

NeuroKit2 0.2.13 的真实直接依赖是 requests、numpy>=2.0.0、pandas<3.0.0、scipy、scikit-learn>=1.0.0、matplotlib>=3.5.0、PyWavelets>=1.4.0、setuptools<82.0.0。其 full extra 额外加入 cvxopt、mne、opencv-python 等大量并非 EDA 最小程序所需的组件。因此默认不要安装/打包 neurokit2[full]。这些组件还各自有间接依赖和二进制运行库，必须全量锁定与盘点。

来源：v0.2.13 pyproject.toml（https://raw.githubusercontent.com/neuropsychology/NeuroKit/v0.2.13/pyproject.toml），0.2.13 PyPI JSON（https://pypi.org/pypi/neurokit2/0.2.13/json）。

建议第一版采用“完整标准发行包 + 自己很薄的 adapter 函数 + 固定版本 + 对照测试”。这里的完整包不等于启用 full extra，也不等于所有算法都纳入产品。优点是更易复核上游行为和接收修复；代价是依赖、导入和冻结包可能较大。NeuroKit2 的顶层 __init__.py 会导入 matplotlib、numpy、pandas、scipy、sklearn 及多个子包，因此仅把导入语句改成子模块路径，不能当作已经消除了顶层导入和依赖。

来源：v0.2.13 顶层初始化源码（https://raw.githubusercontent.com/neuropsychology/NeuroKit/v0.2.13/neurokit2/__init__.py）。

“只复制 1–2 个函数”可作为后期体积优化，但先列出完整调用闭包和许可来源。例如 eda_clean 还引用 NeuroKitWarning、as_vector、signal_filter、signal_smooth；eda_peaks 还引用 find_closest、signal_formatpeaks、eda_findpeaks、eda_fixpeaks。摘下外层函数不意味着自包含，也不意味着 NumPy/SciPy/pandas 已不再需要。

来源：eda_clean 源码（https://raw.githubusercontent.com/neuropsychology/NeuroKit/v0.2.13/neurokit2/eda/eda_clean.py），eda_peaks 源码（https://raw.githubusercontent.com/neuropsychology/NeuroKit/v0.2.13/neurokit2/eda/eda_peaks.py）。

若确需 vendor，应保存：上游项目、版本/commit、原文件与函数、原始版权/许可、修改记录、递归辅助函数清单、测试数据来源、数值对照结果。MIT 允许有条件复制，不是无条件抹掉原作者和许可；“引用论文”也不能替代软件许可。不要把上游整个包都称作自己原创算法。

4. cvxEDA、CVXOPT、CVXPY 的边界

- cvxEDA 官方仓库明确 GPL-3.0；其 Python 项目要求 Python>=3.8、numpy>=1.16、cvxopt>=1.3.1。原始算法程序可以用 Python 运行，不要求 MATLAB，但可分发性必须按 GPL 处理。
- CVXOPT 官网明确 GPL 第 3 版或后续版本；PyPI 的 1.3.3 已有 cp312 Windows x64 wheel。注意 PyPI 的 License 字段只写了“CVXOPT version 1.3”，不能因此误判为宽松许可，必须读官方全文。
- NeuroKit2 eda_phasic 的 cvxEDA 路径实际导入 cvxopt；NeuroKit2 的 MIT 顶层许可不覆盖外部 CVXOPT 的许可，也不能据此忽略所选方法的代码来源审查。
- 若希望闭源分发，cvxEDA/CVXOPT 应列为发布前的许可决策门槛。可选择满足 GPL 的分发方案、取得适当授权、或依据公开数学描述独立实现并验证。用子进程/插件隔离不是自动免责结论，不能直接复制 GPL 函数后换成另一个求解器就宣称许可已解决。

来源：cvxEDA 官方仓库（https://github.com/lciti/cvxEDA），cvxEDA pyproject.toml（https://raw.githubusercontent.com/lciti/cvxEDA/main/pyproject.toml），cvxEDA 许可（https://github.com/lciti/cvxEDA/blob/main/LICENSE.txt），CVXOPT 官方许可（https://cvxopt.org/copyright.html），CVXOPT 发布页（https://pypi.org/project/cvxopt/），NeuroKit2 eda_phasic 源码（https://raw.githubusercontent.com/neuropsychology/NeuroKit/master/neurokit2/eda/eda_phasic.py）。

CVXPY 是建模层，不是 cvxEDA 的无缝替代实现，也不是单一求解器。核验的 1.9.3 要求 Python>=3.11，有 cp312 Windows x64 wheel；主体 Apache-2.0。它的直接依赖还包括 OSQP、Clarabel、SCS、HiGHS、qdldl、sparsediffpy、NumPy、SciPy。若选它，需要单独实现模型、核对边界/正则项/参数单位、固定求解器与容差、检查求解状态，并分别审计实际打包求解器的许可。不能把“CVXPY 是 Apache-2.0”推导为其全部可选商业或 GPL 求解器都受同一许可。

来源：CVXPY 发布页（https://pypi.org/project/cvxpy/），v1.9.3 依赖声明（https://raw.githubusercontent.com/cvxpy/cvxpy/v1.9.3/pyproject.toml），CVXPY 许可（https://raw.githubusercontent.com/cvxpy/cvxpy/master/LICENSE）。

5. PySide6 / Qt 的分发义务

PySide6 wheels 已带 Qt 二进制，开发机器不必另外安装整套 Qt。若选 LGPL 路线，需要针对实际使用的 Qt 模块确认许可，保留许可和版权信息，显著说明使用 Qt，按要求提供对应 Qt 源码或有效源码提供方式，允许用户替换/重新链接相应库并运行替换后的版本，不以 EULA 或技术措施剥夺相关权利；修改 Qt 的部分还应按适用条款提供。部分 Qt 组件可能只有 GPL 或商业选项，不能把全部 Addons 当作统一 LGPL。

one-folder 的可见 DLL 布局通常更容易设计替换和排错流程，但“使用动态 DLL / one-folder”本身并不等于已经完全合规，仍应验证实际分发物。商业 Qt 授权是另一条路线，不应把“商业软件只能买商业 Qt”当作一般规则。本段是工程风险清单，应由项目的许可负责人或合格法律人员结合分发方式复核。

来源：Qt LGPL/GPL 义务（https://www.qt.io/development/open-source-lgpl-obligations），Qt for Python 第三方许可（https://doc.qt.io/qtforpython-6/licenses.html），PySide6 Getting Started（https://doc.qt.io/qtforpython-6/gettingstarted.html）。

6. GUI、CLI 与 EXE 发布设计

建议分层：

- core：读取后标准化的数据、预处理、分解、峰检测、特征、统计，纯函数风格，返回普通数组/表格/字典。
- adapters：对 NeuroKit2、可选分解器、可选 GPU 的窄包装；显式版本和参数，错误统一转换为可解释消息。
- CLI：命令行参数转成与 GUI 同样的配置，调用同一分析入口，产生同格式报告/结果。
- GUI：PySide6 QtWidgets 组合现成控件、普通函数回调；可用 QTimer 轮询后台任务结果，避免为了进度显示把数值核心改成 Qt 类。

Qt 自身是面向对象库，“不自定义 OOP”可以指不写自定义类/继承层次，不能误解为不实例化任何 Qt 对象。官方最小 QtWidgets 教程也展示直接创建控件的使用方式：QtWidgets 入门（https://doc.qt.io/qtforpython-6/tutorials/basictutorial/widgets.html）。

冻结发布应在 Windows 构建，并先验证 one-folder 后再考虑 one-file。后者启动时通常解压到临时目录，排错、启动耗时、异常退出和权限场景更复杂。GUI 与 CLI 两个入口可以共享同一个 core，而不是维护两套算法。

来源：PyInstaller 工作原理与 one-folder/one-file（https://pyinstaller.org/en/stable/operating-mode.html），PyInstaller 平台要求（https://pypi.org/project/pyinstaller/）。

后台计算不能阻塞 GUI 主线程。第一版先串行建立可信基线，再采用有限线程或标准库 multiprocessing / ProcessPoolExecutor；主入口保护与 freeze_support 必须正确，工作进程不得重建 GUI。PyInstaller 官方明确只支持标准库 multiprocessing，其他 Python 多进程框架不是其受支持路径。因此 joblib 默认 loky 不能直接作为“已验证 EXE 批处理方案”；可保留为源码运行/专门测试通过后的可选项，或根据工作负载使用线程后端。还应避免进程数 × BLAS 线程数叠加造成过度并行。

来源：PyInstaller 多进程陷阱（https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html），Python concurrent.futures（https://docs.python.org/3.12/library/concurrent.futures.html）。

7. GPU：只加速经过证明的瓶颈

建议默认 CPU。常规单通道 EDA 的短序列滤波、少量特征计算、逐文件 I/O 和 GUI 绘制不应先承诺 GPU 更快。GPU 候选限于大批量、可批处理的卷积/FFT/矩阵运算，或未来真正需要的学习模型；cvxEDA/CVXOPT、statsmodels、pandas 也不会因为安装 CuPy/PyTorch 自动转到 GPU。

CuPy 14.2.0 官方安装文档列出 Python 3.10–3.14 和 Windows x64 测试平台，需要匹配 NVIDIA GPU/CUDA 运行环境。其当页已测 NumPy 列表到 2.4、SciPy 到 1.17，不能拿 CPU 候选的 NumPy 2.5.4 / SciPy 1.18.0 直接宣称 GPU 组合也已获验证。CuPy 主体 MIT，CUDA 组件各有许可与驱动约束。来源：CuPy 安装矩阵（https://docs.cupy.dev/en/stable/install.html），CuPy LICENSE（https://raw.githubusercontent.com/cupy/cupy/main/LICENSE）。

PyTorch 当前发布页可见 2.14.1 的 cp312 Windows x64 wheel；安装指南列 Windows Python 3.10–3.14，并区分 CPU 与 CUDA 安装。其主体有 BSD 风格许可，但当前发布元数据列出多个组件许可，不能只写“BSD 一项就够”。如果没有机器学习或专门的张量批处理需求，不应仅为宣传 GPU 支持把它放入默认 EDA 包。

来源：PyTorch 发布页（https://pypi.org/project/torch/），官方安装指南（https://pytorch.org/get-started/locally/），PyTorch LICENSE（https://raw.githubusercontent.com/pytorch/pytorch/main/LICENSE）。

GPU 验证必须计入数据传输、初始化、JIT 编译、峰值内存和完整端到端耗时，并用同步后的 GPU 计时；同时比较 CPU/GPU 数值偏差，保留自动 CPU 回退和用户可见的后端记录。CuPy 官方说明第一次调用可能有数秒 CUDA context 开销，并强调异步执行会使普通 CPU 计时产生误判。CuPy 性能最佳实践（https://docs.cupy.dev/en/stable/user_guide/performance.html）。

8. 发布前必须补的实测与产物

本次未执行以下步骤，因此报告中不能写“已通过”。下一阶段应设置这些验收门：

1. 在选定 Windows x64 与可信已修补 Python 运行时上求解并固定完整依赖；验证 wheel 取得方式、哈希、许可证，不把本文版本表当 requirements.lock。
2. 建立 CPU 串行基准，记录算法/包版本、采样率、单位、参数、输入哈希与随机种子；正常、短序列、NaN/缺失、平坦、异常长度数据均覆盖。
3. GUI 与 CLI 同输入同参数结果一致；后台任务、取消、重复启动、错误提示、导出路径都经过测试。
4. 先构建 one-folder，覆盖 Qt plugins、Matplotlib backend/字体、动态导入、NumPy/SciPy 本机 DLL；不因为打包工具宣称支持就省去验证。
5. 在未装 Python/MATLAB/CUDA 的干净 Windows 机器离线启动 CPU 版；测试普通用户权限、中文/空格路径、只读安装目录和真实批量数据。
6. 并发测试必须使用冻结后的 EXE，核验不会无限 spawn、不重复弹 GUI、可以退出、内存不失控。GPU 版另有驱动/硬件/容差矩阵。
7. 输出 SBOM/第三方许可目录、版权和 NOTICE、cvxEDA/Qt 的许可决策记录、可重复构建记录与安全更新计划。正式对外分发前处理代码签名和安装/卸载体验。

最终措辞建议：“优先验证 Python 3.14/Windows x64 作为发布架构，Python 3.12 保留为兼容备选；已发现 NeuroKit2 与 pandas 3.x 的约束冲突，将通过约束锁定规避。最终组合仍须通过依赖解析、数值回归、冻结打包和干净 Windows 环境验收后确认。”
